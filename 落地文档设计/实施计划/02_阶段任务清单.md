# 阶段任务清单

> 目标：将各阶段拆解为可执行任务，并要求每个任务遵循完整闭环：开发 → 自测 → SIT → UAT → 终版 → 回归 → 里程碑确认。

## 一、阶段 0：工程基座与环境准备

### 任务 0.1：工程骨架与环境构建
- 目标：搭建后端/前端脚手架、环境、CI/CD
- 产物：
  - backend 工程
  - frontend 工程
  - docker-compose
  - Flyway
  - 开发规范与分支策略
- 验收：
  - 能一键启动
  - health 接口正常
  - 所有基础脚本可跑
- 测试要求：
  - 单元测试：基础配置类
  - 集成测试：环境启动
  - 回归：环境重启后可用

### 任务 0.2：数据库 DDL 与迁移
- 目标：创建初始表结构和分区维护脚本
- 产物：31 张基础表、分区逻辑、淘汰任务
- 验收：
  - 表创建成功
  - 分区脚本可执行
  - Flyway 迁移可回滚
- 测试要求：
  - 表结构校验
  - 迁移回归
  - 升级/回滚脚本验证

### 任务 0.3：统一基础设施
- 目标：统一日志、异常、traceId、错误码、JWT
- 产物：
  - Result 封装
  - 统一异常处理
  - 鉴权中间件
- 测试要求：
  - 单测覆盖异常响应
  - 接口链路测试

### 任务 0.4：数据源长样本探针（硬门禁）
- 目标：确认五源采集稳定性
- 产物：
  - 3 日探针报告
  - 成功率、完整率、延迟分析
- 验收：
  - 东财、雪球、同花顺、腾讯、新浪都达到门禁要求
- 结论：
  - 未达标则停线重评，不允许进入下一阶段

## 三、阶段 2：采集链路与数据治理

### 任务 2.1：采集调度器
- 目标：实现扫描/执行分离、任务调度、任务状态
- 产物：
  - 调度器
  - task instance 记录
  - 失败重试机制
- 测试要求：
  - 调度任务执行
  - 超时与失败重试
  - 回归验证

### 任务 2.2：限流与熔断
- 目标：保障源站不被封禁，且任务稳定
- 产物：
  - rate limiter
  - circuit breaker
  - 403 即开路
- 测试要求：
  - QPS 控制验证
  - 熔断回闭合验证
  - 退避恢复验证

### 任务 2.3：东财/雪球/同花顺采集
- 目标：通过三源采集链路
- 产物：
  - Adapter
  - raw record 写入
- 测试要求：
  - 采集成功率验证
  - 重跑幂等验证
  - 字段完整率验证

### 任务 2.4：行情快照采集
- 目标：支持实时行情快照和互备切换
- 产物：
  - 来源适配器
  - Redis 缓存快照
- 测试要求：
  - 数据精度验证
  - 切换策略验证

### 任务 2.5：治理流程
- 目标：清洗、去重、实体识别、质量评分
- 产物：
  - clean worker
  - dedup worker
  - entity worker
  - quality worker
- 测试要求：
  - 广告过滤测试
  - 去重召回率测试
  - 实体识别test
  - 质量评分回归

### 任务 2.6：死信与回放
- 目标：保证失败任务可追踪、可回放
- 产物：
  - dead letter 表
  - replay orchestrator
- 测试要求：
  - 单条失败不影响批次
  - 回放恢复验证

## 七、任务执行强制要求

每个任务都必须包括：

1. 需求与设计确认
2. 开发
3. 自测
4. SIT
5. 修复与回归
6. UAT
7. 终版确认
8. 回归测试
9. 里程碑确认

且任何一个环节不通过，任务不能视为完成。

## 八、任务结束判定标准

任务仅在以下情况下可视为“完成”：

- 功能完成
- 单元测试通过
- 集成测试通过
- SIT/UAT 通过
- 修复的缺陷已回归
- 测试报告已归档
- 阶段里程碑确认已签字

任何缺陷被上移到下一阶段，视为项目管理违规。
