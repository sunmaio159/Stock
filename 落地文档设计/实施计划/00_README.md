# 实施计划总览

> 版本：V1.0（2026-10-03）
> 目标：为团队提供一套可执行的实施路线图与周任务清单，确保每个阶段均遵循“任务完成→测试完成→回归完成→里程碑确认→才能进入下一阶段”的硬门禁规则，杜绝堆积屎山代码和功能越界。

## 一、总体原则

1. 每个阶段只允许进入下一阶段的前提条件：
   - 当前阶段任务已完成；
   - 单元测试通过；
   - 集成测试通过；
   - 回归测试通过；
   - 里程碑确认完成。
2. 禁止在未完成当前阶段目标的情况下开启下一阶段开发。
3. 每个任务必须遵守：开发 → 自测 → SIT → UAT → 终版修正 → 回归 → 里程碑确认。
4. 所有新功能必须经过评审，严禁将 V2/V3 功能硬塞进 V1。
5. 任何阶段出现问题，必须回滚到上一阶段稳定点后再继续推进。

## 二、总体路线

项目按以下六个阶段推进：

- 阶段 0：工程基座与环境准备
- 阶段 1：账户、主数据、词典冷启动
- 阶段 2：采集链路与数据治理
- 阶段 3：情感分析与指数生成
- 阶段 4：工作台、详情页、WS 与告警
- 阶段 5：联调、压测、SIT/UAT、上线前验收

目标交付：V1 MVP，运行稳定，数据可靠，可回放，可观测。

## 三、阶段门禁规则

每个阶段都需要通过以下门禁：

1. 功能完成率达到目标值；
2. 单元测试覆盖达到要求；
3. SIT 通过；
4. UAT 通过；
5. 回归测试通过；
6. 里程碑确认通过；
7. 需求/缺陷已闭环，且无高优先级未修复问题。

只有满足以上条件，才能开始下一阶段。

## 四、任务执行模型

每个任务必须按以下流程执行：

- 需求评审
- 设计确认
- 开发
- 自测
- SIT 测试
- 问题修复
- UAT 测试
- 终版确认
- 回归测试
- 里程碑确认
- 进入下一任务

## 六、版本管理原则

- 每个阶段任务一旦完成，需要在版本库中打 tag 或生成阶段版本。
- 任何修复都必须回写对应 issue / defect。
- 任何发生在 SIT/UAT 中的缺陷必须修复并重新回归后才能进入下一阶段。
- 不允许把“已知缺陷”直接带到下一阶段。

## 七、开发规则

1. 先设计，后编码。
2. 先单测，后集成。
3. 先回归，后上线。
4. 每个阶段都必须做停机审查与风险评估。
5. 每个阶段必须保留可回退版本。

## 八、结束语

本实施计划是项目执行的硬性依据。所有人员必须遵守阶段门禁规则和质量闭环机制，确保项目在 6 周内稳定交付 V1 MVP，而不是堆积大量后期无法解决的技术债。
