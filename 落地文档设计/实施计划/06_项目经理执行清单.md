# 项目经理执行清单

> 版本：V1.0（2026-10-03）
> 适用：项目经理、技术负责人、测试负责人、产品负责人、开发负责人
> 目标：确保项目严格执行“阶段门禁 + 测试闭环 + 回归验证 + 里程碑确认”的管理机制。

## 一、总体执行规则

1. 任何阶段仅允许在上一阶段完成并确认后启动。
2. 每个任务必须有明确责任人。
3. 每个任务必须有明确交付物、验收标准和测试证据。
4. 任何缺陷必须写入缺陷池，并明确修复责任人和关闭时间。
5. 未通过 SIT/UAT 的功能，不允许进入下一阶段。
6. 里程碑确认必须由项目经理组织签字确认，签字前不得宣布阶段完成。

---

## 二、项目经理每日/每周检查清单

### 1. 每日检查

- [ ] 当前阶段任务进度是否符合计划
- [ ] 是否存在未完成的关键依赖任务
- [ ] 是否存在未关闭高优先级缺陷
- [ ] 是否存在“开发后直接提交但未测试”的情况
- [ ] 是否有功能堆积到下一阶段的趋势
- [ ] 是否有关键数据源异常或反爬信号
- [ ] 是否存在测试回归未完成的问题
- [ ] 是否已生成当日任务状态更新

### 2. 每周检查

- [ ] 阶段目标是否完成
- [ ] 当前周测试是否完成并归档
- [ ] 回归是否全部通过
- [ ] 是否需要启动里程碑确认
- [ ] 是否存在跨阶段风险传递
- [ ] 是否有需要砍减的需求或延期项
- [ ] 是否需要召开阶段复盘会

## 三、团队责任分工清单

### 1. 项目经理

- [ ] 负责项目总进度管理
- [ ] 审核阶段目标是否达成
- [ ] 确认里程碑是否达到标准
- [ ] 组织阶段例会与风险评审
- [ ] 对抛出的未闭环问题负责协调
- [ ] 确认进入下一阶段的门禁是否满足

### 2. 技术负责人

- [ ] 负责技术方案执行
- [ ] 确认开发是否符合设计和架构
- [ ] 解决技术风险和依赖问题
- [ ] 审核测试环境与配置是否稳定
- [ ] 确认回滚方案是否具备

### 3. 开发负责人

- [ ] 确认任务分解与交付物
- [ ] 执行开发任务并提交测试版本
- [ ] 处理自测和 S I T 过程中暴露的问题
- [ ] 确保代码质量和可回溯性
- [ ] 不允许未测试代码提交到已定义稳定分支

### 4. 测试负责人

- [ ] 设计测试范围
- [ ] 执行 SIT/UAT
- [ ] 收集和跟踪缺陷
- [ ] 组织回归测试
- [ ] 出具测试结果和结论
- [ ] 确认风险是否已处置

### 5. 产品负责人

- [ ] 确认需求是否明确且可落地
- [ ] 审核功能是否满足业务目标
- [ ] 参与 UAT 和验收确认
- [ ] 对不在 V1 范围内的需求进行拦截
- [ ] 确认里程碑是否符合业务预期

## 六、项目经理判断清单

在每次阶段结束前，项目经理必须回答以下问题：

- [ ] 当前阶段是否真的完成，而不是“功能做出来但未测试”
- [ ] 当前阶段是否存在未修复的高优先级缺陷
- [ ] 是否存在临时补丁或隐性技术债
- [ ] 是否有新的需求被悄悄塞进来
- [ ] 下一阶段是否有足够的缓冲时间
- [ ] 是否有明确回滚方案
- [ ] 是否已经完成里程碑确认

---

## 七、项目闭环要求

项目在每个阶段的结束时必须形成以下材料：

- 阶段版测试报告
- 缺陷清单
- 回归结论
- 里程碑确认表
- 下一阶段启动审批

只有当这些材料齐备并确认后，才允许正式进入下一阶段。

---

## 八、执行底线

项目经理必须严格执行以下底线：

- 不允许未测试代码进入下一阶段
- 不允许未回归缺陷进入下一阶段
- 不允许“已知遗留问题”被忽略
- 不允许在没有里程碑确认的情况下宣布阶段完成
- 不允许在没有项目负责人签字的前提下开始下一个阶段

只有遵守底线，项目才可能在 6 周内稳定交付 V1 MVP，而不是堆砌代码和后期返工。
