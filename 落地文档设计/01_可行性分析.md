# 01 可行性分析

> 版本：V2.1（2026-10-03）｜ 全套文档统一版本号以 00_README 为准

> 结论先行：**V1 在 1-2 人、6 周、年成本 ≤¥2 万的约束下可行**，核心风险集中在数据源稳定性与 L1 情感准确率两项，均有降级路径。以下是逐项论证。

## 一、技术可行性

### 1.1 技术栈成熟度

| 技术点 | 成熟度 | 依据 |
|---|---|---|
| Spring Boot 3 + MyBatis-Plus + MySQL + Redis | ✅ 极成熟 | 主流组合，无探索成本 |
| 进程内队列流水线（LinkedBlockingQueue 分段） | ✅ 成熟 | 5 万帖/日 ÷ 86400s ≈ 0.6 帖/s 均值，峰值按 20 倍计 12 帖/s，4 线程治理（单条约 50ms）吞吐 80 帖/s，**6 倍余量** |
| SimHash64 + 分桶比对 | ✅ 可实现 | 单帖比对 <5ms（桶内 <100 候选 × popcount） |
| AC 自动机实体抽取 | ✅ 可实现 | 词典 ~1.5 万模式（5400 股×名称+别名），构建 <1s，匹配 O(n) |
| L1 规则情感引擎 | ✅ 可实现，⚠️ 准确率依赖词典 | 纯 CPU 内存计算；准确率 75% 门槛靠词典迭代达成（见 §四风险 R2） |
| WebSocket STOMP 单机推送 | ✅ 成熟 | 50 并发用户 × 3 连接 = 150 长连接，单机无压力 |
| 东财/雪球/同花顺舆情采集 | ⚠️ 有条件可行 | 公开页面/接口；风险在反爬（§四 R1）；另有腾讯/新浪行情备源提高行情可用性 |

### 1.2 数据源策略（五源可配置）

舆情三源：东财（主）/雪球/同花顺；行情三源：东财（主）/腾讯/新浪（互为备份，自动切换）。全部通过可配置 Adapter 接入（02 §二），新增源多数情况零代码。

### 1.3 数据量与容量测算（V1，6 个月）

| 项 | 测算 | 结论 |
|---|---|---|
| 日采集帖量 | 活跃股吧 ~2000 吧 × 日均 25 帖 ≈ 5 万帖 | 与目标一致 |
| 采集 QPS | 2000 吧 / 300s 周期 ≈ 7 QPS 峰值，限流 5 QPS | 一轮 ~7min 超出 5min 周期 → **需分组交错**（活跃吧两组各 ~1000 吧，单组 ~3.3min），实际可行 |
| MySQL 写入 | 峰值 ~50 TPS（raw+doc+result 三表） | 单机 MySQL 轻松承载 |
| 存储 | raw 30 天 ~3.6GB + doc 90 天 ~9GB + result ~2.3GB + 其余 <1GB | **~16GB**，50GB 盘余量 3 倍 |
| 详情页查询 | 聚合 7 卡并行，热数据 Redis 命中 >90% | P95 ≤800ms 可达 |
| 内存 | JVM 4G：SimHash 桶 + AC Trie(~50MB) + 词典 + 队列驻留 | 4C8G 机器充足 |

### 1.4 关键技术验证（W0-W2 必须实测的先决条件）

| # | 验证项 | 通过标准 | 失败降级 |
|:-:|---|---|---|
| V1 | 舆情三源 3 日长样本探针（~144 轮/源，见 06 §W0.4） | 东财 ≥99% / 雪球 ≥97% / 同花顺 ≥95% | 任一不过则降频；主源不过则切换主源（排期 +3 天） |
| V2 | 行情三源（东财/腾讯/新浪）3 日盘中探针 | 任一源 ≥99.5%；腾讯/新浪以**东财为基准源**交叉比对，偏差 ≤0.5% | 至少一源过线即可；多源互备兜底 |
| V3 | L1 词典冷启动 | 500 条标注集 ≥75% | 词库扩至 1500 词 + 标题分权可调（默认 0.6） |
| V4 | SimHash 误判率 | 抽检 ≤5% | 汉明阈值 3→2 |

## 二、资源与进度可行性

**6 周排期的底层核算**（方案 B：后端 1 + 前端 1×4 周）：

| 周 | 后端人日 | 前端人日 | 缓冲 |
|---|---|---|---|
| W0 奠基 | 3-5 | 1 | — |
| W1 账户+主数据+词典 | 5 | 5 | 词典可延至 W3 前 |
| W2 采集 | 5 | （前端工作台） | +20% 反爬缓冲 |
| W3 治理+情感 | 5 | （详情页框架） | +20% 词典调优 |
| W4 指数+页面 | 4 | 5 | — |
| W5 WS+告警 | 5 | 5 | — |
| W6 联调压测 | 5 | 2 | 零新功能 |

后端合计 ~32 人日 vs 可用 33 人日——**紧但可行**；若落后，按范围守门砍顺序：雪球/同花顺降为一源（东财）→ 告警仅站内 → 词云降级为 Top 词表。

## 四、风险可行性（Top 5 及降级路径）

| # | 风险 | 概率 | 降级路径 | 残余风险 |
|---|---|---|---|---|
| R1 | 东财反爬封禁 | 高 | 降频→切雪球/同花顺主源；行情另有腾讯/新浪双备源自动切换 | 低（舆情三源+行情三源互备） |
| R2 | L1 准确率 <75% | 中 | 词典迭代 + 标题分权 + UI 标注"参考信号" | 低（产品定位为参考信号，非决策依据） |
| R3 | 6 周排期滑期 | 中 | 范围守门砍单（§二） | 低 |
| R4 | 单机故障 | 中 | 日备+binlog，RTO ≤1h | 低（内部工具可容忍） |
| R5 | 合规（UGC 采集展示） | 低 | 摘录 ≤200 字+原文跳转+脱敏+免责，已内置设计 | 低 |

## 五、不可行项与边界（明确声明）

1. V1 **不可能**做到：全市场 5000 股实时舆情覆盖（只覆盖活跃 ~2000 吧 + 自选股）、情感准确率 >85%（需 L2 模型，V3）、7×24 高可用（单机）
2. 短信验证码通道视主体资质而定——**邮箱验证码为保底通道**，两者同一套契约
3. 情绪指数不构成投资建议，产品形态受合规约束（见 04 §3.5）

## 六、总结论

**GO**。建议按方案 B（后端 1 + 前端 1）启动，W0 先完成 §1.4 的 V1/V2 两项验证（五源 3 日长样本探针，方案见 06 §W0.4）——这是整个项目唯一的"一票否决"环节，验证不过则退回重新评估数据源策略，损失 ≤5 人日。
