# 06 流水线运行手册（V1.3 修订版）

> V1.3 修订要点：① 修正背压策略（P-02）；② 新增补偿回放机制；③ 修正备份策略（S-06）；④ 新增监控指标；⑤ 扩容故障演练场景。

## 1. 线程与队列全景（V1.3 修订）

```
scan线程(1) ──分发──> crawlExecPool(8, AbortPolicy, 有界队列64) ──upsert──> MySQL  [V1.3]
                              │ 投递(限时3s)                             [V1.3]
                              ▼
                    governQueue(10000) → governPool(4) ──单条事务──> MySQL
                              │ 合格(quality≥2 且非重复)
                              ▼
                    sentimentQueue(10000) → sentimentPool(2) → L1引擎(纯CPU)
                              │
                              ▼
                    派生调度: 15min滚动 / 日频17:00 / 突增检测(V1环比)
                              │
                              ▼
                    alertEvalPool: 价格组(30s) + 派生组(15min)           [V1.3]
                              │
                              ▼
                    推送池(2)
```

**[V1.3] 行情快照独立线程**：
```
QuoteSnapshotScheduler(单线程, 交易日09:25-15:05每3s, 非交易日每5min)
  → 批量拉取 → Redis quote:snapshot:{code} + market:summary:{date} → 收盘落 m6_quote_daily
```

### 队列满策略（V1.3 修订）

| 水位 | 动作 |
|---|---|
| < 50% | 正常 |
| 50%-80% | 记 `pipeline_queue_size`，无额外动作 |
| > 80% | WARN 日志 + `pipeline_queue_high` 指标，采集端开始记 pending（`parse_status=0`）|
| = 100% | P1 告警 + 上游 `offer(doc, 3s)`，超时记 pending，**绝不无限阻塞** |

### 补偿回放（V1.3 新增，P-02）

```
BacklogReplayer(每60s):
  SELECT id FROM m3_raw_record WHERE parse_status=0 AND fetched_date >= CURDATE()-1 LIMIT 500
  → 重新 parse → governQueue.offer(doc, 3s) → 成功则 UPDATE parse_status=1

启动补偿:
  on ApplicationReady → 同上查询 → 批量重投
```

## 2. 异常处理矩阵（V1.3 修订）

| 异常 | 处理 | 恢复 | 变更 |
|---|---|---|---|
| HTTP 超时/5xx | 重试 ≤3（退避 1/2/4s）| 连续 5 次→熔断开路 | — |
| 403/验证码特征 | 立即开路 + P0 企微告警 | 运营手动半开 | — |
| 治理队列满 | **限时 3s + 记 pending + 照常提交游标** | BacklogReplayer 补投 | **[V1.3]** |
| DB 写失败 | 重试 3 次 → 本地磁盘 buffer | DB 恢复后扫描 buffer 回放 | — |
| 治理单条失败 | 重试 3 次 → `m4_dead_letter` | 死信重试任务（每小时）| — |
| 进程 crash | 重启后 `parse_status=0` 被启动补偿自动补投 | 对账 diff=0 | **[V1.3]** |
| 行情源失效 | `marketSnapshot=null` + `X-Degraded: quote`，价格告警挂起 | 行情恢复后自动恢复 | **[V1.3 新增]** |
| 推送失败 | 重试 3 次，`push_status=2` | 渠道恢复后补偿推送 | — |

## 3. 幂等链（V1.3 修订）

`m3_raw_record.uk(source, outer_id, fetched_date)` → `m4_normalized_doc.uk(source, outer_id)` → `m5_sentiment_result.uk(doc_id, engine_level)`。

**[V1.3] 补偿语义**：`parse_status` 作为补偿事实源，确保"不重复、且至多延迟 5min 补投、不丢失"。

## 4. 对账（每日 02:00，不变）

```
采集入库数 = 治理产出 + 去重标记 + 无实体丢弃 + 死信
差异率 > 0.1% → 告警 + 自动生成差异报告
```

## 6. 故障演练清单（V1.3 扩至 7 场景）

| # | 注入 | 预期 | 验收 |
|---|---|---|---|
| 1 | 东财源返回 403 | 立即开路 + P0 告警；雪球/同花顺照常 | 告警 ≤1min 到企微 |
| 2 | kill Redis | 详情页/工作台降级回源 MySQL（P95≤2s）+ 告警 | 无 5xx 雪崩 |
| 3 | kill MySQL 30s | 采集落磁盘 buffer，恢复后自动回放 | 对账 diff=0 |
| 4 | 治理队列灌满 | 采集不永久阻塞，sourceLock 正常释放，pending 可回放 | 恢复后自动消化，diff=0 |
| 5 | 企微 webhook 失效 | push_status=2，站内信兜底 | 事件不丢 |
| **6** | **行情源失效** | `marketSnapshot=null` + `X-Degraded: quote`，价格告警挂起不误报 | 无 5xx，降级标签可见 | **[V1.3 新增]** |
| **7** | **进程强杀（kill -9）** | 重启后 `parse_status=0` 自动补投，对账 diff=0 | 消息不丢 | **[V1.3 新增]** |

## 7. 备份策略（V1.3 修订，S-06）

| 对象 | 方式 | 频率 | 保留 | 变更 |
|---|---|---|---|---|
| 核心表 | **`mysqldump --single-transaction` 周全备** | 每周日 03:00 | 本地 1 周 + 每月异地 1 份 | **[V1.3] 由"日备"改为"周全备"** |
| binlog | 开启，expire 7 天 | 实时 | 7 天（PITR）| 不变 |
| m3_raw_record | 不单独备份（30 天窗口，重采可补）| — | — | 不变 |
| Redis | RDB 每日 | 每日 | 3 天 | 不变 |

> **[V1.3] 存储量估算**：周全备 ≈15GB + 7 天 binlog ≈5GB ≈ **20GB**（匹配 50GB 盘）。
> 备份告警：`backup_last_success_hours > 26h` → P0；`backup_size_bytes` 环比骤降 >30% → 告警（防空备份）。

恢复演练：每季度一次"从备份恢复到干净机器"全流程，RTO ≤ 1h。

## 8. 合规清单（V1.3 增强，C-08 升级）

1. 帖文展示：摘录 ≤200 字 + `originUrl` 跳源站；不整篇转载
2. 作者脱敏：昵称显示首字+***；`author_id` 存 SHA-256，不存源站原始 ID
3. 免责声明：页脚"数据来源于公开渠道，仅供参考，不构成投资建议"；**不可关闭、不可折叠**
4. 采集自律：遵守 robots.txt；单源 QPS ≤ 5；UA 真实标注；不为绕反爬使用账号池/打码平台
5. 数据处理：用户数据仅自用不二次分发；注销用户 30 天内物理删除其自选/规则数据
6. **商用前法务评估**：列入上线硬门禁；付费用户协议中明示数据来源与用途 **[V1.3 新增]**
7. **投诉下架**：提供投诉入口 + 72h 响应机制 **[V1.3 新增]**
