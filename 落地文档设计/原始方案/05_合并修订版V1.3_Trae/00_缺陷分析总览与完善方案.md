### 1.2 评审方法

采用 **三层交叉验证**：
1. **文档内一致性**：同文档前后描述是否自洽
2. **跨文档一致性**：库表 ↔ API ↔ 页面 ↔ 计划 是否互相支撑
3. **可执行性推演**：按文档能否直接写出代码并跑通全链路

## 四、关键决策记录

| 决策 | 选项 | 结论 | 理由 |
|---|---|---|---|
| 行情来源 | A:公开接口快照 / B:降级收盘价 / C:付费API | **A** | 成本零、量小、有降级；支撑全部 V1 交付物 |
| 线程池拒绝策略 | AbortPolicy / CallerRunsPolicy / 自定义阻塞 | **AbortPolicy + 有界队列 64** | 扫描永不被阻塞，背压可观测 |
| 治理队列背压 | 无限阻塞 / 限时阻塞+补投 / 丢弃 | **限时阻塞 3s + pending 补偿** | 保有锁释放 + 宕机可恢复 |
| 登录方式 | 短信 / 邮箱 / 邀请码 | **双通道（短信+邮箱）** | 短信有资质门槛，邮箱零成本兜底 |
| 备份策略 | 全量日备 / 周全备+日增备 / 流式上传 | **周全备+日增备(binlog)** | 存储量降至~20GB，匹配 50GB 盘 |

## 五、完善原则

1. **最小改动路径**：V1.3 只修 P0/P1，P2 标注"V2 实施"，不扩大 V1 范围
2. **向后兼容**：新增列默认可空或默认值；新增表不影响现有逻辑
3. **可执行优先**：所有 DDL 补丁以 Flyway `V1.3__fix.sql` 形式组织，可直接执行
4. **单事实源不变**：03=表结构、04=API、05=实现准绳——修订后的约定仍以此为准
