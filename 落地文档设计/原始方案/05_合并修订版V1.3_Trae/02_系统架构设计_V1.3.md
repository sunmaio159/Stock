# 02 系统架构设计（V1.3 修订版）

> 来源：分册 A 阶段2.1，经两轮评审修订。
> V1.3 修订要点：① 新增行情快照采集架构（A-01）；② 修正线程池策略（P-01）；③ 修正背压策略（P-02）；④ 缓存防护（C-06）；⑤ 演进接口预留清单（C-07）；⑥ 全局追踪标识约定（C-09）；⑦ 情绪指数公式修正（ALG-01~05）。
> **部署形态：V1 单机单实例**（多实例是 V4 项，WebSocket 的多实例广播设计仅为预留）。

## 一、六层架构（V1.3 修订）

```
数据源层  东财股吧/雪球/同花顺(V1) + 公开行情接口(V1.3 快照) → RSS/公告/行情/资金/财报(V2+)
   ↓ 唯一外部交互层
采集层    调度器(扫描线程+执行池分离) → Adapter插件 → Raw Lake(m3_raw_record,30天)
   │       + QuoteSnapshotScheduler(交易日盘中 3s，收盘落 m6_quote_daily) [V1.3 新增]
   ↓ 进程内阻塞队列(限时阻塞 3s)
治理层    Clean → Dedup(SimHash64+分桶) → Entity(AC自动机) → Quality → m4_normalized_doc
   ↓ 队列投递
分析层    BudgetRouter → L1规则引擎 → m5_sentiment_result → 情绪指数(日频+15min,修正公式) → 突增检测
   ↓
应用层    工作台/详情页聚合/选股/告警引擎(倒排索引)/WS推送/搜索
   ↓
终端层    Vue3 Web（移动H5 V2）+ 企微/钉钉 webhook
```

**层间铁律**：上层只依赖直接下层；采集层是唯一与外部数据源交互的层；行情数据**直通应用层**，不进治理流水线（符合现有层间铁律）。

## 三、四条流水线（V1.3 口径）

### 3.1 采集流水线

```
scanAndDispatch(单线程,30s) → 取启用且到期源(m3_source_config.cron)
→ 防重入锁(AtomicBoolean per source) → 提交执行池(AbortPolicy,队列满→catch + 下轮重试)
→ 熔断检查(真三态,见下) → 令牌桶限流(RateLimiter per source,真实发放)
→ Adapter.fetch(带增量游标,DB为准) → RawRecord落库(幂等 upsert, fetched_date 为应用层写入的 DATE)
→ Adapter.parse → Schema校验(漂移P1阻断/P2P3放行记日志)
→ 投递治理队列(offer 3s超时; 超时→记 pending, 照常提交游标) [V1.3 修订]
→ 整批成功后更新 last_cursor → 记账(m3_task_instance, 部分成功记 status=3/PARTIAL) [V1.3 修订]
```

#### 行情快照采集（V1.3 新增，A-01）

```
QuoteSnapshotScheduler(交易日 09:25-15:05 每 3s, 非交易日 每 5min)
  → 构建标的集: 自选股 ∪ 告警 scope 展开 ∪ 三大指数 ∪ 涨跌家数
  → 批量拉取(单次 50-100 代码, QPS ≈ 0.3-1, 低于自律上限)
  → Redis quote:snapshot:{code} (TTL 30s) + market:summary:{date} (TTL 5min)
  → 收盘 15:05 落 DB m6_quote_daily 一份
  → 行情源失败 → marketSnapshot=null + X-Degraded: quote
  → 复用 m3_source_config(source_type=5) 的熔断与记账
```

**三态熔断器（定稿语义，不变）**：
- 闭合 → 连续失败 5 次 → 开路（记录 `circuit_open_until`）
- 开路到期 → **半开**：放行恰好 1 个探测请求；成功→闭合并清零失败计数；失败→重新开路且等待时间指数退避（30s→2min→10min→30min 封顶）
- HTTP 403 / 验证码特征 → 不等 5 次立即开路 + P0 告警（反爬特征优先于次数）

### 3.2 治理流水线（V1.3 修订 P-02）

```
governQueue(10000) → 消费线程池(4)
  每条文档: Clean → Dedup → Entity → Quality → persist(单条事务) → 合格则投递情感队列
  单条失败重试3次 → m4_dead_letter；绝不阻塞整批
```

**背压策略（V1.3 修订）**：
- 上游投递：`governQueue.offer(doc, 3, TimeUnit.SECONDS)`，超时记 `pendingBacklog`（存 `m3_raw_record.parse_status=0`），采集照常提交游标
- `BacklogReplayer`：每 60s 扫描 `parse_status=0` 记录 → 队列水位<50% 时重新 parse → 投递
- **队列满绝不无限阻塞**，避免持有 sourceLock 的采集线程长冻

**队列水位分级**：

| 水位 | 动作 |
|---|---|
| < 50% | 正常 |
| 50%-80% | 记 `pipeline_queue_size`，无动作 |
| > 80% | WARN 日志 + `pipeline_queue_high` 指标，采集端开始记录 pending |
| = 100% | P1 告警 + 上游停止投递（限时 3s 超时即 pending）|

**启动补偿**：应用启动 / 每 5min 扫描 `m3_raw_record WHERE parse_status=0 AND fetched_date >= CURDATE()-1` → 重新投递治理队列。

### 3.3 情感流水线（V1.3 修订 ALG 公式）

```
情感队列 → BudgetRouter(V1恒L1) → L1规则引擎
→ m5_sentiment_result(engine_level=实际执行级别, dict_version + algo_version)
→ 15min滚动聚合(m5_sentiment_index_15m, 仅交易日盘中)
→ 日频终值(交易日17:00, m5_sentiment_index)
→ 突增检测(V1仅环比模型; V2加Z-Score+情绪反转)
→ 命中 → M8告警引擎
```

**情绪指数（V1.3 修正公式，量纲 [0,100]）**：

```
Si = 50 + 50 × Σ(wk_eff × score_k) / Σ(wk_eff)        # 量纲 [0,100]，中性 50

wk_eff = w_account × w_time × w_source × w_quality × w_interaction × conf_factor

w_account     = max(0.1, kol_score / 100)              # V1 恒 0.1（kol_score 默认 10）
w_time        = clamp(0.5^(Δt_hours / 24), 0.05, 1.0)  # Δt<0（盘后帖）取 Δt=0 → 1.0，不放大了
w_source      = 东财 1.0 / 雪球 0.9 / 同花顺 0.9        # 存 m3_source_config，可配置
w_quality     = quality_score / 5                       # [0.2, 1.0]
w_interaction = clamp(ln(1 + interaction_count), 0.5, 3.0)  # [V1.3 修正] 防单帖绑架
conf_factor   = 0.3 (hit_count=0) | 0.6 (confidence<0.3) | 1.0 (其他)  # [V1.3 修正] 防止零命中拉平

score_k ∈ [-1, 1]，来自 L1 引擎 tanh 输出
```

**空值语义（三条，缺一不可）**：

| 场景 | `sentiment_index` | `post_count` | `sample_post_count` | 前端 |
|---|---|---|---|---|
| 当日无任何帖 | `NULL` | 0 | 0 | "—"（无数据）|
| 有帖但全部无情感命中/低置信 | `NULL` | n | 0 | "暂无有效情绪信号" |
| 有有效样本 | 计算值 | n | m | 数值 + 温度计 |

> V1.3 修订点：① w_account V1 恒 0.1（KOL 缺省 10，作者画像表冷启动）；② w_time 盘后帖不放大（Δt<0 取 Δt=0 → 1.0），加下限 0.05 和上限 1.0；③ conf_factor 降低零命中样本对指数的拉平作用；④ w_interaction clamp [0.5, 3.0] 防止爆帖绑架；⑤ sample_post_count=0 时返回 NULL 而非静默 50。

### 3.4 投研流水线（不变）

V1：情绪指数 → 详情页舆情卡；聚合模型 = 七卡片 CompletableFuture 并行（每卡超时 500ms，超时返回 `{available:false}`，总预算 700ms）。
V3 目标态：五维因子（z-score 行业标准化）× 表化权重 → 综合评分 + 归因 + 每日快照。

**缓存防护（V1.3 新增，C-06）**：
- **TTL 抖动**：所有固定 TTL 加 ±10% 随机抖动，防缓存雪崩
- **空值缓存**：不存在的标的/无数据的指数缓存 NULL 标记（TTL 1min，防穿透）
- **热点本地缓存**：三大指数行情在 JVM 内 Caffeine 缓存（TTL 3s，防 Redis 热点）
- **回源限流**：Redis 不可用时每个 key 每秒最多回源 MySQL 1 次（Guava RateLimiter）

游标**不存 Redis**——以 `m3_source_config.last_cursor` 为唯一事实源。

## 五、安全设计（V1.3 修订）

- 认证：JWT AT 2h + RT 7d；RT 旋转（每次刷新换发新 RT，旧 RT 作废）；`sys_sms_code` 存哈希不存明文；**新增 `sys_email_code`**（邮箱验证码，OPS-01）
- 鉴权：RBAC 两角色起步（USER / ADMIN），`/api/admin/**`、`/api/crawl/**` 需 ADMIN
- 限流：API 网关层单用户 60 req/min；搜索 20 req/min；登录验证码 1条/min、10条/天/号
- Web 安全：CORS 白名单、参数化查询（MyBatis `#{}`）、企微 webhook URL 存 DB 加密字段、密码 BCrypt
- **敏感配置加密**：`m3_source_config.crawl_params` 中 `cookie/ua` 字段加密存储（AES-256-GCM，密钥 `AQUILA_SECRET_KEY` 环境变量注入）；解密后的值只在内存中存活，不落日志 **[V1.3 新增]**
- 合规：帖文展示摘录 ≤200 字 + 原文链接跳转源站；作者昵称脱敏（首字+***）；页脚免责声明；遵守 robots.txt 与频率自控
