## 5.1 采集调度器（V1.3 修订）

### 设计要点（V1.3 修订）
1. **扫描与执行分离**：单线程 `scheduleAtFixedRate(30s)` 只做扫描分发；任务执行用独立 `ThreadPoolExecutor(8, AbortPolicy) + 有界队列 64` **[V1.3 修订：原 CallerRunsPolicy 阻塞扫描]**。
2. **限流真实发放**：每源一个 Guava `RateLimiter`，**QPS 变更 30s 内生效**（后台改 `rate_limit_qps` 后，定时刷新 `limiters` Map，不用 `computeIfAbsent` 一劳永逸）**[V1.3 修订 OPS-05]**。
3. **游标 DB 为准**：`m3_source_config.last_cursor` 唯一事实源；整批处理成功后才更新 DB。
4. **三态熔断**：真三态 + 半开探测 + 指数退避；403/验证码特征立即开路+P0 告警。
5. 记账：每任务一行 `m3_task_instance`；**部分成功记 status=3（PARTIAL）而非 FAILED** [V1.3 修订 P-04]；反爬中断时已有记录入库 → 记部分成功并提交游标，不反复重采已成功的页。
6. **敏感配置加密**：`crawl_params` 中 cookie/ua 字段 AES-256-GCM 加密存储，解密后仅内存存活 **[V1.3 新增 A-03]**。

### 关键骨架（V1.3 修订版）

```java
@Component
public class CrawlScheduler {
    private final ThreadPoolTaskScheduler scanner;   // poolSize=1, 仅扫描
    private final ThreadPoolExecutor execPool;       // [V1.3] AbortPolicy + 有界队列64
    private final Map<String, AtomicBoolean> sourceLocks = new ConcurrentHashMap<>();
    private final Map<String, RateLimiter> limiters = new ConcurrentHashMap<>();
    private volatile long limitersVersion = 0;       // [V1.3] QPS 热更新版本号

    {
        execPool = new ThreadPoolExecutor(
            8, 8, 0L, TimeUnit.MILLISECONDS,
            new ArrayBlockingQueue<>(64),             // [V1.3] 有界队列
            new ThreadFactoryBuilder().setNameFormat("crawl-exec-%d").build(),
            new ThreadPoolExecutor.AbortPolicy());    // [V1.3] 关键：不用 CallerRunsPolicy
    }

    void scanAndDispatch() {
        if (!running.get()) return;
        refreshLimitersIfNeeded();                    // [V1.3] QPS 热更新
        for (SourceConfig src : sourceConfigService.selectDue(LocalDateTime.now())) {
            AtomicBoolean lock = sourceLocks.computeIfAbsent(src.getSourceCode(), k -> new AtomicBoolean());
            if (!lock.compareAndSet(false, true)) continue;
            try {
                execPool.execute(() -> { try { executeWithGuard(src); } finally { lock.set(false); } });
            } catch (RejectedExecutionException e) {
                lock.set(false);                      // [V1.3] 释放锁，下轮再试
                Metrics.counter("crawl_task_skipped", "source", src.getSourceCode()).increment();
                log.warn("crawl exec pool full, skip sourceCode={}", src.getSourceCode());
            }
        }
    }

    void executeWithGuard(SourceConfig src) {
        if (!circuitBreaker.allow(src)) { Metrics.counter("crawl_circuit_skip", ...); return; }
        TaskInstance run = taskService.start(src);
        int successCount = 0;                         // [V1.3] 追踪部分成功
        try {
            RateLimiter limiter = getLimiter(src);
            CrawlResult result = adapterRegistry.get(src).fetch(src, limiter);
            rawRecordService.batchUpsert(result.records(), run.getId());
            successCount = result.recordCount();
            var docs = adapter.parse(result.records());
            driftDetector.check(src, docs);
            governancePipeline.submit(docs);          // [V1.3] 改为限时阻塞投递
            sourceConfigService.commitCursor(src.getSourceCode(), result.newCursor());
            circuitBreaker.onSuccess(src);
            taskService.finish(run, successCount == result.totalExpected()
                ? "SUCCESS" : "PARTIAL", successCount, null);  // [V1.3]
        } catch (AntiCrawlException e) {
            if (successCount > 0) {
                sourceConfigService.commitCursor(src.getSourceCode(), result.newCursor());
                taskService.finish(run, "PARTIAL", successCount, "anti-crawl after " + successCount + " records");
            } else {
                taskService.finish(run, "FAILED", 0, e.getMessage());
            }
            circuitBreaker.openImmediately(src);
            alertService.p0("源被反爬: " + src.getSourceCode());
        } catch (Exception e) {
            if (successCount > 0) {
                taskService.finish(run, "PARTIAL", successCount, e.getMessage());
            } else {
                circuitBreaker.onFailure(src);
                taskService.finish(run, "FAILED", 0, e.getMessage());
            }
        }
    }

    // [V1.3] QPS 热更新：每 30s 检查 rate_limit_qps 变更，刷新对应 RateLimiter
    void refreshLimitersIfNeeded() {
        long latestVersion = sourceConfigService.getMaxUpdatedAtEpoch();
        if (latestVersion > limitersVersion) {
            limiters.clear();
            limitersVersion = latestVersion;
        }
    }
}
```

## 5.2 治理流水线（V1.3 修订）

### 设计要点（V1.3 修订）
1. **背压改为限时阻塞 + 补偿**：`governQueue.offer(doc, 3, TimeUnit.SECONDS)`；超时记 `parse_status=0`（不阻塞持有 sourceLock 的采集线程）；`BacklogReplayer` 每 60s 补投 **[V1.3 修订 P-02]**。
2. **启动补偿**：应用启动 / 每 5min 扫描 `m3_raw_record WHERE parse_status=0 AND fetched_date >= CURDATE()-1 LIMIT 500` → 重新 parse → 投递。
3. **队列水位分级**：<50% 正常 / 50-80% 记指标 / >80% WARN + 采集端记 pending / =100% P1 告警 + 上游停止投递。
4. 单条事务 + 死信；情感分析移出治理事务；Clean/Dedup/Entity/Quality 逻辑不变。

```java
// [V1.3] 采集线程投递治理队列（替换原阻塞 put）
boolean ok = governQueue.offer(doc, 3, TimeUnit.SECONDS);
if (!ok) {
    Metrics.counter("pipeline_offer_timeout", "queue", "govern").increment();
    // parse_status=0 已由 rawRecordService 写入，BacklogReplayer 自动补偿
    log.warn("govern queue full, doc will be replayed via parse_status=0, rawId={}", doc.getRawRecordId());
}
// 不抛异常、不阻塞；采集照常提交游标
```

|---|---|---|
| **E21** | 治理队列满 → 上游无限阻塞 → sourceLock 长冻 | 限时 3s + parse_status 补偿 |

### 5.3.3 情绪指数（V1.3 修正公式，ALG-01~05）

```
Si = 50 + 50 × Σ(wk_eff × score_k) / Σ(wk_eff)        # 量纲 [0,100]

wk_eff = w_account × w_time × w_source × w_quality × w_interaction × conf_factor

w_account     = max(0.1, kol_score / 100)              # V1 恒 0.1（kol_score 全默认 10）
w_time        = clamp(0.5^(Δt_hours / 24), 0.05, 1.0)  # [V1.3] Δt<0（盘后帖）取 Δt=0 → 1.0，不放大了
w_source      = 东财 1.0 / 雪球 0.9 / 同花顺 0.9
w_quality     = quality_score / 5
w_interaction = clamp(ln(1 + interaction_count), 0.5, 3.0)  # [V1.3] 防爆帖绑架
conf_factor   = 0.3 (hit_count=0)                      # [V1.3] 防止零命中拉平
              | 0.6 (0 < confidence < 0.3)
              | 1.0 (confidence ≥ 0.3)
```

**V1.3 修正说明**：

| 修正 | 问题 | 修正 |
|---|---|---|
| ALG-01 | `w_account(KOL/100)` 无数据源 | V1 恒 0.1（作者画像表 kol_score 默认 10）→ 排序由其他因子主导 |
| ALG-02 | 盘后帖 Δt<0 → 权重 >1 | Δt<0 取 Δt=0 → w_time=1.0；加下限 0.05 和上限 1.0 |
| ALG-03 | score=0 样本全额进入分母 → 指数被拉向 50 | conf_factor 降权 + sample_post_count=0 → 返回 NULL |
| ALG-04 | 板块指数重复计帖（一帖多股） | 板块聚合前 `SELECT DISTINCT doc_id` 去重 |
| ALG-05 | `log(1+互动数)` 无上限 | clamp [0.5, 3.0] |

**作者画像加载**：启动时全量加载 `m5_author_profile` 到内存 Map（<100MB），每 30min 增量刷新；未命中 → w_account=0.1。

## 5.5 告警引擎（V1.3 修订）

### V1 实现范围（V1.3 修订 A-02）

**1）构建规则倒排索引（Redis，规则变更时重建）**：
```
rules:by:security:{code}  → [ruleId...]
rules:by:watchlist:{gid}  → [ruleId...]
rules:by:metric:{metric}  → [ruleId...]
```

**2）按指标自然周期分组调度**：

| 指标 | 评估周期 | 说明 |
|---|---|---|
| `price` | 30s（盘中）| 依赖行情快照 |
| `sentiment_index` | 15min | 与 15min 派生表同频 |
| `volume_ratio` | 15min（V1 可降为 60min）| 声量环比 |

**3）指标值先算后匹配**：对每个被关注的标的算一次指标值 → 广播给订阅它的规则。复杂度从 O(R×S) 降为 O(S+命中)。

**4）降噪三件套（不变）**：
- 冷却：`alert:cooldown:{rule}:{code}` SETNX（仅在确认触发后占位）
- 日上限：`alert:daily:{rule}:{code}:{date}` incr（首次 setnx 2d TTL）
- 合并：`dedup_key` 唯一索引兜底

**5）用户级免打扰（V1.3 新增 C-10）**：
- 用户可设置免打扰标的/来源列表
- 评估时检查：若 `securityCode ∈ muteList.securities` 或 `sourceCode ∈ muteList.sources` → skip

**6）夜间勿扰 + 补发**：quiet_hours 时段内仅 priority ≤ minPriority 放行，其余**缓存到 08:00 补发**；补发时**再过一次降噪**（冷却+日上限）**[V1.3 增强]**。

### V2 目标（不变）
DSL 条件树、表单可视化编辑器、规则回测 API、dingtalk/email 渠道。
