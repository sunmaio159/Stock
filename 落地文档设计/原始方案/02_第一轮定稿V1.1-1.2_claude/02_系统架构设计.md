# 02 系统架构设计（定稿）

> 来源：分册 A 阶段2.1，经评审修订。**部署形态：V1 单机单实例**（多实例是 V4 项，WebSocket 的多实例广播设计仅为预留）。

## 一、六层架构

```
数据源层  东财股吧/雪球/同花顺(V1) → RSS/公告/行情/资金/财报(V2+)
   ↓ 唯一外部交互层
采集层    调度器(扫描线程+执行池分离) → Adapter插件 → Raw Lake(m3_raw_record,30天)
   ↓ 进程内阻塞队列
治理层    Clean → Dedup(SimHash64+分桶) → Entity(AC自动机) → Quality → m4_normalized_doc
   ↓ 队列投递
分析层    BudgetRouter → L1规则引擎 → m5_sentiment_result → 情绪指数(日频+15min) → 突增检测
   ↓
应用层    工作台/详情页聚合/选股/告警引擎/WS推送/搜索
   ↓
终端层    Vue3 Web（移动H5 V2）+ 企微/钉钉 webhook
```

**层间铁律**：上层只依赖直接下层；采集层是唯一与外部数据源交互的层；行情/资金/财报数据**不走**治理流水线（`NormalizedDoc` 仅承载文本类文档，行情落 `m6_quote_daily` 等专用表，V2）。

## 三、四条流水线（定稿口径）

### 3.1 采集流水线

```
scanAndDispatch(单线程,30s) → 取启用且到期源(m3_source_config.cron)
→ 防重入锁(AtomicBoolean per source) → 提交执行池
→ 熔断检查(三态,见下) → 令牌桶限流(RateLimiter per source,真实发放)
→ Adapter.fetch(带增量游标,DB为准) → RawRecord落库(幂等 upsert)
→ Adapter.parse → Schema校验(漂移P1阻断/P2P3放行记日志)
→ 投递治理队列 → 整批成功后更新 last_cursor → 记账(m3_task_instance)
```

**三态熔断器（定稿语义）**：
- 闭合 → 连续失败 5 次 → 开路（记录 `circuit_open_until`）
- 开路到期 → **半开**：放行恰好 1 个探测请求；成功→闭合并清零失败计数；失败→重新开路且等待时间指数退避（30s→2min→10min→30min 封顶）
- HTTP 403 / 验证码特征 → 不等 5 次立即开路 + P0 告警（反爬特征优先于次数）

### 3.2 治理流水线

```
governQueue(10000) → 消费线程池(4)
  每条文档: Clean → Dedup → Entity → Quality → persist(单条事务) → 合格则投递情感队列
  单条失败重试3次 → m4_dead_letter；绝不阻塞整批
```

- Clean：去 HTML（Jsoup Safelist）→ 广告正则（词表入库热更新）→ 繁简转换（opencc4j）→ 正文截断 **5000 字**、标题 100 字
- Dedup：SimHash64 + 汉明 ≤3；Redis 索引**按高 16 位分桶**比对；溢出按时间桶淘汰最旧，禁止整删
- Entity：AC 自动机，词典 = `m2_security`(名称) + `m2_security_alias`(简称/俗名/拼音)；多实体取提及最多者为主标的，全部写 `m4_entity_mention`；词典变更 Redis pub 通知**双 buffer 重建**自动机
- Quality：扣分制（短内容/广告词/高频作者/重复）+ 互动加分 → `quality_score 1-5`

### 3.3 情感流水线

```
情感队列 → BudgetRouter(V1恒L1) → L1规则引擎
→ m5_sentiment_result(engine_level=实际执行级别)
→ 15min滚动聚合(m5_sentiment_index_15m, 仅交易日盘中)
→ 日频终值(交易日17:00, m5_sentiment_index)
→ 突增检测(V1仅环比模型; V2加Z-Score+情绪反转)
→ 命中 → M8告警引擎
```

**情绪指数（定稿公式，量纲 [0,100]）**：

```
Si = 50 + 50 × Σ(wk × score_k) / Σ(wk)，score_k ∈ [-1,1]，无数据 → NULL
wk = w_account(KOL/100, 下限0.1) × w_time(0.5^(Δt/24h), Δt以交易日收盘时刻为基准)
   × w_source(东财1.0/雪球0.9/同花顺0.9) × w_quality(quality/5) × log(1+互动数)
```

> 修订点：①量纲从 [-100,100] 改为 [0,100]；②时间衰减基准从 `now()` 改为**收盘时刻**，保证同一交易日的指数可复现；③无数据返回 NULL，前端显示 "—"。

### 3.4 投研流水线（V1 最小段 + V3 目标态）

V1：情绪指数 → 详情页舆情卡；聚合模型 = 七卡片 CompletableFuture 并行（每卡超时 500ms，超时返回 `{available:false}`，总预算 700ms）。
V3 目标态：五维因子（z-score 行业标准化）× 表化权重 → 综合评分 + 归因 + 每日快照（`ana_factor_def` / `ana_factor_value` / `ana_stock_score` / `ana_stock_score_history`）。

## 四、Redis Key 规范（定稿）

| Key 模式 | 内容 | TTL |
|---|---|---|
| `watchlist:{userId}` | 自选股缓存 | 30min，写时刷新 |
| `quote:snapshot:{code}` | 行情快照 | 10s |
| `sentiment:latest:{code}` | 最新情绪指数 | 24h |
| `simhash:bucket:{code}:{bucket}` | SimHash 分桶索引 | 24h |
| `quality:author:{source}:{authorId}` | 作者 24h 发帖计数 | 24h（incr+首次setnx） |
| `alert:cooldown:{ruleId}:{code}` | 告警冷却 | = 规则 cooldown |
| `alert:daily:{ruleId}:{code}:{date}` | 日触发计数 | 2d |
| `crawl:ratelimit:{source}` | 限流窗口计数 | 1s |
| `sentiment:budget:{level}:{date}` | L2/L3 日预算 | 2d |
| `channel:user:{userId}` | WS 跨实例广播频道（V4 预留） | — |

游标**不存 Redis**——以 `m3_source_config.last_cursor` 为唯一事实源（评审 P0-4 修订）。

## 五、安全设计（定稿）

- 认证：JWT AT 2h + RT 7d；RT 旋转（每次刷新换发新 RT，旧 RT 作废）；`sys_sms_code` 存哈希不存明文
- 鉴权：RBAC 两角色起步（USER / ADMIN），`/api/admin/**`、`/api/crawl/**` 需 ADMIN
- 限流：API 网关层单用户 60 req/min；搜索 20 req/min；登录验证码 1条/min、10条/天/号
- Web 安全：CORS 白名单、参数化查询（MyBatis `#{}`）、企微 webhook URL 存 DB 加密字段、密码 BCrypt
- 合规：帖文展示摘录 ≤200 字 + 原文链接跳转源站；作者昵称脱敏（首字+***）；页脚免责声明；遵守 robots.txt 与频率自控
