## 设计基线仲裁规则（最高优先级约定）

1. 任何文档间冲突时，**以本文件夹 00-10 文档为准**；原始设计稿仅作历史参考。
2. 表结构与字段以 [03_数据库设计.md](03_数据库设计.md) 为唯一事实源；伪代码中出现的 `crawl_task_run`/`doc_post` 等旧表名一律映射到本方案表。
3. API 以 [04_API契约.md](04_API契约.md) 为唯一契约；前后端不得私自增减字段。
4. 核心口径统一：
   - **情绪指数量纲 [0, 100]**，中性 = 50，无数据 = `null`（不是 50，更不是 0）
   - **评分卡权重**：基本面 0.25 / 估值 0.20 / 资金面 0.20 / 技术面 0.20 / 舆情情绪 0.15，权重存 `ana_factor_def`，代码中禁止硬编码
   - **时间基准**：全系统 `Asia/Shanghai`；所有"日"级调度与比较必须过交易日历 `m2_trade_calendar`，禁止用 `MON-FRI` 或 `minusDays(1)` 代替
5. **行情数据口径（V1.2 新增，A-01）**：V1 采集**实时行情快照**（自选股 ∪ 告警 scope ∪ 三大指数 ∪ 全市场涨跌家数），落 `m6_quote_daily`（提前启用）与 Redis，**不走治理流水线**；V1 不做历史日K/分钟K采集（V2）。行情不可用时降级为最近收盘价并置 `stale=true` / `X-Degraded: quote`。
6. **归属维度铁律（V1.2 新增）**：所有用户可见资源（自选股明细、告警事件、推送渠道）必须冗余 `user_id` 并由**服务端强制过滤**，禁止从请求参数取 `userId`。
7. **版本化追溯（V1.2 新增）**：情感结果与情绪指数必须记录 `dict_version` + `algo_version`；词典变更单调升版本并可回滚。
8. **幂等维度（V1.2 修订）**：`m3_raw_record` 幂等维度是**采集日**（`fetched_date`，非秒级时刻），分区方案为 `RANGE COLUMNS(fetched_date)`。
9. V1 范围以 [01_需求与范围基线.md](01_需求与范围基线.md) §五 为准。

## 一句话定位

**Aquila 是面向个人投资者/小团队的 A 股投研工具，以「采集→治理→情感→投研」四条流水线为骨架，提供一屏式个股研报视图和智能告警触达。V1 单机单实例部署，6 周交付 MVP，年成本 ≤ ¥2 万。**
