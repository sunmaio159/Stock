# 04 情感算法口径缺陷修正方案

> 对应总览 `00` 中的 ALG-01 ~ ALG-05，以及交叉评审新增的 **C-03（情绪指数作为二级参考信号）**。
> 定位：修订 `02 §3.3` 的情绪指数公式与 `05 §5.3` 的实现规范。
> 说明：现有公式的**骨架是正确的**（加权平均 + [0,100] 量纲 + 收盘基准 + NULL 语义），本轮修正的是**依赖缺失、边界失控、样本污染**三件事。

---

## ALG-01（P1）`w_account` 依赖不存在的 KOL 数据

### 问题

`02 §3.3` 定义 `wk = w_account(KOL/100, 下限 0.1) × ...`，但全套 22 张表中：
- 无任何作者表；
- `m4_normalized_doc` 只有 `author_id`（SHA-256 脱敏）与 `author_name`，**无 KOL 标识、无粉丝/影响力分值**；
- `m5_sentiment_dict` 是词表，与作者无关。

即 `KOL` 这个变量**在整个系统中没有定义来源**，公式不可实现。

### 修正方案

**1）新增作者画像表（V1 建表、V2 才真正填充）**

```sql
CREATE TABLE `m5_author_profile` (
  `id`             bigint       NOT NULL AUTO_INCREMENT,
  `source_code`    varchar(32)  NOT NULL,
  `author_id`      varchar(64)  NOT NULL COMMENT 'SHA-256脱敏作者ID',
  `author_name`    varchar(64)  DEFAULT NULL COMMENT '脱敏昵称(展示用,可不存)',
  `is_kol`         tinyint      NOT NULL DEFAULT 0 COMMENT '0否 1是',
  `kol_score`      decimal(5,2) NOT NULL DEFAULT 10.00 COMMENT '[0,100],V1默认10',
  `post_count_30d` int          NOT NULL DEFAULT 0,
  `avg_quality`    decimal(3,2) DEFAULT NULL,
  `updated_at`     datetime     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_source_author` (`source_code`, `author_id`),
  KEY `idx_kol` (`is_kol`, `kol_score`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='作者画像(情绪指数 w_account 的数据来源)';
```

**2）V1 冷启动策略（明确写死，避免实现时各做各的）**

> **V1 `kol_score` 缺省 10 → `w_account = max(0.1, 10/100) = 0.1`，对所有作者恒定。**
> 由于指数是**加权平均**，`w_account` 恒定会在分子分母中约去，因此 **V1 指数的排序与区分度完全由 `w_time / w_source / w_quality / w_interaction` 决定**——这在数学上等价于"V1 暂不启用 KOL 权重"，是可接受且自洽的降级，不会出现"隐含随机权重"。

**3）运营后台提供 KOL 标记入口**（V1 可选、V2 必做）：数据源看板 → 高频作者列表 → 人工标记 `is_kol` 并给 `kol_score`。

**4）计算时如作者画像缺失**：不做 DB 实时查询（每帖一次查询会拖垮情感流水线），改为**启动时全量加载到内存 Map**（V1 作者量级 < 100 万，Map 内存 < 100MB），每 30min 增量刷新；未命中 → 默认 0.1。

## ALG-02（P1）`w_time` 在盘后帖上被放大

### 问题

```
w_time = 0.5^(Δt/24h)，Δt = 交易日收盘时刻 − 帖发布时间
```

当帖在**收盘之后**发布（15:00 之后，乃至 20:00、23:00），`Δt < 0` → 指数为正 → `w_time > 1`，且越晚发权重越大（如 Δt = −8h → `w_time = 2^(8/24) ≈ 1.26`）。

后果：**盘后灌水帖的权重高于盘中实时帖**，这与"越接近收盘的信息越有价值"的设计意图完全相反，且给了刷帖者可乘之机（收盘后集中发帖即可绑架次日指数）。

### 修正

```
Δt_hours = (收盘时刻 − 发布时间) / 1h
若 Δt_hours < 0（盘后发布）：
    归入当日但取 Δt_hours = 0  →  w_time = 1.0（与收盘时刻帖同权，不再放大）
w_time = clamp(0.5^(Δt_hours / 24), 0.05, 1.0)
```

- 下限 `0.05`：避免 7 天前的帖子权重趋近 0 却仍占用分母（同时呼应"默认近 7 天窗口"）；
- 上限 `1.0`：硬封顶，杜绝任何放大。

**配套口径声明**（写入 02 §3.3）：
> 盘后（15:00 之后）发布的帖子**计入当日指数**（因为 17:00 计算时它们已存在，且盘后舆情对次日开盘有指示意义），但 `w_time` 一律取 1.0，不再获得"比收盘更近"的额外加权。

## ALG-03（P1）零命中样本系统性拉平指数

### 问题

`05 §5.3.1` 输出 `score = tanh(ΣfinalScore / 3)`，未命中任何情感词时 `Σ=0 → score=0`。

而指数公式 `Si = 50 + 50 × Σ(wk × score_k)/Σ(wk)` 中，**`score=0` 的样本依然以 `wk` 全额进入分母**。后果：

- 一只股票当天有 100 条帖，其中 90 条是"无情感倾向的水帖"（score=0），10 条是强烈看多（score=0.8）→ 指数 ≈ 50 + 50×(10×w×0.8)/(100×w) ≈ **54**，看起来"中性偏暖"；
- 文档花大力气定义了"**无数据 = NULL（不是 50）**"，却又让"有数据但无情感信号"的场景**静默回到 50 附近**——这是同一类问题的另一种表现形式，属于**口径不一致**。

### 修正（两档，建议都做）

**档一：低置信样本降权（V1 必做，改动小）**

```
w_effective = wk × conf_factor
conf_factor = 0.3                     若 hit_count = 0（未命中任何情感词）
            = 0.6                     若 0 < confidence < 0.3
            = 1.0                     若 confidence ≥ 0.3
```

即"水帖"仍计入（保留声量信息），但**对指数方向的拉平作用被削减到 30%**。

**档二：有效样本不足时返回 NULL（V1 必做，语义补齐）**

```
sample_post_count = 满足 confidence ≥ 0.3 的样本数
若 sample_post_count = 0：
    sentiment_index = NULL（而非 50），并在响应中标注 reason = "NO_VALID_SAMPLE"
```

这与 `S-07` 新增的 `m5_sentiment_index.sample_post_count` 列直接对应，前端展示"暂无有效情绪信号"，与"无数据 —"区分开（更友好）。

**修订落点**：`05 §5.3.3` 公式段、`04 §5` `sentiment/index` 响应增加 `samplePostCount` 字段、`08` 新增 TC-021。

## ALG-04（P1）板块指数重复计帖

### 问题

`05 §5.2.6` 规定"全部实体写 `m4_entity_mention`"，即**一帖可命中多只股票**。而 `05 §5.3.3` 规定"板块指数 = 成分股按帖量加权"。

若一帖同时提及板块内 A、B 两只股，则在板块聚合时该帖被计 2 次 → `post_count` 虚高 → 声量突增检测在板块维度必然误报（V2 板块突增会直接踩坑）。

### 修正

```
板块聚合前先做文档级去重：
  SELECT DISTINCT doc_id FROM m4_entity_mention m
    JOIN m2_industry_member im ON im.security_code = m.security_code
   WHERE im.industry_code = :code AND m.published_at BETWEEN ...
板块 post_count = 上述 DISTINCT doc_id 的计数（不是 SUM(成分股 post_count)）
```

**配套**：`m5_sentiment_index` 中 `scope_type='INDUSTRY'` 行的 `post_count` 注释改为"**去重后的文档数**"，并在 `03 §5` 表注释中同步说明，避免后续误用。

## ALG-05（P2）`w_interaction` 无上限

`w_interaction = log(1 + 互动数)`，理论上界 `log(1+100000) ≈ 11.5`。一个 10 万互动的爆帖，其权重可达普通帖（10 互动，`log(11)≈2.4`）的 **4.8 倍**；若该帖同时是 `w_time=1.0`、`w_quality=1.0`，单帖即可主导整个指数。

**修正**：
```
w_interaction = clamp(ln(1 + interaction_count), 0.5, 3.0)
```
- 下限 0.5：避免 0 互动帖权重为 0 而被完全忽略（新帖发布初期互动为 0，但内容仍有价值）；
- 上限 3.0：单帖影响力封顶为普通帖约 3 倍，保证指数由"群体情绪"而非"单帖"决定。

## 修正后的完整公式（建议直接替换 `02 §3.3`）

```
Si = 50 + 50 × Σ(wk_eff × score_k) / Σ(wk_eff)        # 量纲 [0,100]，中性 50

wk_eff = w_account × w_time × w_source × w_quality × w_interaction × conf_factor

w_account     = max(0.1, kol_score / 100)              # V1 恒 0.1（kol_score 默认 10）
w_time        = clamp(0.5^(Δt_hours / 24), 0.05, 1.0)  # Δt<0（盘后帖）取 Δt=0 → 1.0
w_source      = 东财 1.0 / 雪球 0.9 / 同花顺 0.9        # 存 m3_source_config，可配置
w_quality     = quality_score / 5                       # [0.2, 1.0]
w_interaction = clamp(ln(1 + interaction_count), 0.5, 3.0)
conf_factor   = 0.3 (hit_count=0) | 0.6 (confidence<0.3) | 1.0 (其他)

score_k ∈ [-1, 1]，来自 L1 引擎 tanh 输出
```

**空值语义（三条，缺一不可）**：

| 场景 | `sentiment_index` | `post_count` | `sample_post_count` | 前端 |
|---|---|---|---|---|
| 当日无任何帖 | `NULL` | 0 | 0 | "—"（无数据） |
| 有帖但全部无情感命中/低置信 | `NULL` | n | 0 | "暂无有效情绪信号" |
| 有有效样本 | 计算值 | n | m | 数值 + 温度计 |

**可复现性保证**：
- `w_time` 以**收盘时刻**为基准（已有，保留）；
- `w_account` / `w_source` / `w_quality` 均为确定性取值；
- 新增 `algo_version` + `dict_version` 落库（见 S-07），使"同日同版本重算必得同值"成为可验证命题（`08` TC-011 扩展为"同版本两次重算结果完全一致"）。

## C-03（P1）情绪指数定位为"二级参考信号"（产品级定义）

> 来源：汇报版评审 §三.2 / §六方案三 / §五业务风险"情绪信号误导（高）"。
> ALG-01~05 解决的是"**数算得对不对**"，本节解决"**这个数能不能被当成结论用**"。

### 1. 产品定位声明（写入 07 §4 与免责声明）

> **情绪指数是基于公开舆情文本的统计参考信号，不是投资建议，不构成任何买入/卖出结论。**

三条硬性约束：
1. 情绪指数**永不单独给出方向性结论**，所有展示位必须同时给出**时间窗口**与**近期基准**；
2. 禁止在 UI 出现"推荐""必涨""抄底""逃顶"等措辞；告警文案只能是**事实描述**（"声量较上一交易日同期增长 3.2 倍"），不得是**行动建议**；
3. 页脚与详情页固定展示免责声明（06 §8 已有，此处要求**不可关闭、不可折叠**）。

### 2. `signalLevel` 分级（落库 + 下发，见 03 号文件契约）

| 级别 | 判定条件 | 指数 | 前端 | 告警 |
|---|---|---|---|---|
| `NO_DATA` | `post_count = 0` 或 `sample_post_count = 0` | `NULL` | "—" + 提示 | 不触发 |
| `LOW_SAMPLE` | `sample_post_count < 10` | 计算值 | 数值 + **"样本不足"灰标** | 情绪类告警**不触发** |
| `HIGH_VOLATILE` | 近 5 日 `stdDev > 20` 或 当日环比变动 `> 30` | 计算值 | 数值 + **"波动剧烈"橙标** | 情绪反转类**不触发**（仅保留声量突增） |
| `NORMAL` | 其他 | 计算值 | 数值 + 温度计 | 正常触发 |

### 3. `confidence` 计算（[0,1]，落库并下发）

```
confidence = clamp( f_sample × f_consistency , 0.05, 0.95 )

f_sample      = 1 - exp(-sample_post_count / 30)     # 样本量因子，30 条约 0.63
f_consistency = 1 - min(1, score_stddev / 0.8)       # 样本极性一致性，分歧大则低
```

- `confidence` 只用于**展示与告警门槛**，**不参与指数加权**（加权已由 `conf_factor` 处理，避免二次惩罚）；
- `confidence < 0.3` 时前端显示"低置信"，且不参与红黑榜 Top5 排名（避免噪声标的占据榜单）。

### 4. 极端与异常值的保守处理

| 场景 | 处理 |
|---|---|
| 单日指数跳变 > 40 | 标记 `HIGH_VOLATILE`，**延迟一个 15min 窗口二次确认**后再触发告警 |
| 声量突增但 `sample_post_count` < 10 | 声量告警降级为站内信（不推企微），防刷帖绑架 |
| 连续 3 日 `NO_DATA` | 从红黑榜移除，并在详情页提示"近期无有效舆情样本" |
| 全市场 `NO_DATA` 占比 > 40% | 判定为**采集链路异常**而非市场现象，触发 `sentiment_null_ratio` 告警并暂停指数类告警 |

### 5. 指数失真的回滚与重算（汇报版："谁负责回滚和重算？"）

| 环节 | 责任人 | 动作 | 时限 |
|---|---|---|---|
| **发现** | 监控自动 + 用户反馈入口 | `sentiment_null_ratio` 异常 / 周度相关性观察 / 词典回归准确率下降 >3pp | — |
| **定位** | 运营（ADMIN） | 按 `dict_version` + `algo_version` + `schema_version` 定位变更点（`sys_audit_log` 留痕） | ≤2h |
| **处置** | 运营（ADMIN） | 词典回滚（03 号文件 `POST /api/admin/dict/versions/{v}/rollback`）→ 自动触发受影响 `(code, tradeDate)` 重算 → 刷新缓存 | ≤4h |
| **验证** | 运营 | 跑标注集回归 + 抽检 20 只标的指数前后差异 | ≤8h |
| **复盘** | 负责人 | 写 `sys_audit_log` + 补充回归用例到标注集 | 当周 |

**前置依赖**（缺一不可，否则上述流程无法执行）：S-07 版本化、C-02 审计、C-04 标注集版本、P-03 重放链路、03 号文件回滚 API。

## 配套：L1 引擎的两点补强（非缺陷，属稳健性建议）

1. **否定窗口内的程度副词顺序**：`05 §5.3.1` 已定义"向前看 3 个 token"，但"不太看好"与"不看好"应得到不同强度。建议在 `detail` JSON 中输出每个情感词的 `{word, baseScore, negation, degree, finalScore}`，便于逐条核对准确率（500 条标注集调试时价值极高）。
2. **标题与正文分权**：股吧场景下**标题的情绪强度通常显著高于正文**。建议 `score_doc = 0.6 × score_title + 0.4 × score_content`（标题缺失时全取正文）。这是低成本、高收益的准确率提升手段，建议在 W3 做 A/B（标注集上对比是否提升 ≥3 个百分点）。
