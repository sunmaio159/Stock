## 3. 产品范围与容量

### 3.1 V1 必交付

- 单管理员本地密码、TOTP、一次性恢复码、本机重置、持久会话和审计。
- 沪深证券/别名/交易日历导入与搜索，自选分组、备注、排序、CSV/XLSX 预览导入。
- 手动热门列表及按有效舆情提及量生成的热门候选；人工列表与自动候选分别标识，不暗中互相覆盖。
- 单资讯源的许可策略、采集任务、raw、持久游标、规范化、近似重复关系、证券关联、质量原因和处理恢复。
- 本地规则情绪三分类、[-100,100] 分值、置信度/解释、15 分钟/1 小时/24 小时聚合。
- 工作台、个股详情、帖子、站内声量告警、确认/忽略、来源/词典/死信/受限重放。
- 许可字段 Excel 导出、留存清理、日志指标、原生安装升级、备份恢复和发布检查。

不包含交易执行、持仓/成本/交易记录、个性化建议、买卖指令、目标价/止损/仓位、多租户、公开注册、第二资讯源、行情采集、价格告警、外部通知或外部模型。V1 的研究输出以情绪和声量为准，综合趋势/风险评分须另定输入及验证后再交付。

### 3.2 容量口径

自选与手动热门初始各允许 20 只，后续各最多 300 只。自选上限按管理员所有分组内不同证券去重计数，不按每组分别放宽；同一证券可出现在不同组，采集和分析订阅只计算一次。热门与自选的采集范围按并集去重。此为消除原“各 20 只/每组 20 只”冲突的实施口径，A 阶段冻结时记录。

组数、上传大小、导入行数、导出范围、重放条数和执行预算在 A 阶段配置表中冻结。未配置上限时相应批量功能不可启用，不采用无限默认值。扩容由设备测试、来源许可和管理员批准共同决定。

## 4. 架构与工程边界

单 Java 进程同源提供前端构建产物和 `/api`，MySQL 保存业务事实。模块为 common/config、auth/security、masterdata、watchlist/hotlist、source-policy/crawl、governance、sentiment、workbench、alert、admin/maintenance。

调用方向：Controller → Application Use Case → Domain Service/Repository/Port。Controller 不写 SQL，Adapter 不写游标，Entity 不直接输出 JSON。网络、解析和计算不得放在持锁数据库事务内。

在线请求、采集、治理和维护采用独立有界资源预算；MySQL 连接池总预算受设备容量约束。内存队列只作加速，持久任务是恢复依据。队列满时停止新调度并展示积压，不丢任务、不使用无限队列或 CallerRuns 将重计算转交调度线程。

Redis 不是必需组件，只缓存可重建结果；故障不能放宽认证、撤销、许可或限速。V1 默认先用数据库批量查询与轮询，通过测量后再决定缓存。

## 5. 统一 API 与前端契约

### 5.1 通用规则

响应为 `Result<T>{code,message,data,traceId}`，成功 `code=0`。目标 HTTP 状态：参数 400、未认证 401、无权限/CSRF 403、不存在 404、冲突 409、限流 429、依赖/系统失败 5xx。历史 HTTP 200 业务错误仅是迁移盘点对象；若存在实际调用方，A 阶段制定兼容切换并同步前端，不在模块间混用。

- BIGINT ID、版本号在 JSON 中输出十进制字符串，避免 JavaScript 精度丢失。
- 时间使用 ISO-8601 +08:00；DB DATETIME(3) 保存 Asia/Shanghai 业务时间；内部 Clock 可注入。
- `securityCode` 在 V1 API/关联表采用带市场的规范标识，如 `SH:600000`、`SZ:000001`；导入裸代码须结合市场验证，不能仅按前缀猜测。历史六位代码须经主数据回填和全链路迁移，不直接覆盖原键。
- 字符串枚举大小写一致；列表页码返回 `{items,total,page,size}`，时间线返回 `{items,nextCursor,hasMore}`，size 最大 100。
- 时间线游标绑定过滤条件、排序和签名；按 `(published_at DESC,id DESC)` 稳定翻页。
- 写请求验证会话、CSRF、Origin、字段和资源归属。认证接口不缓存凭证响应。
- 幂等键绑定 user、方法、路径、请求摘要；同键不同内容返回 409。状态与业务结果同事务提交或通过可恢复状态收敛，不保存认证秘密。

### 5.3 状态与页面

`DataCard<T>` 固定包含 `state,asOf,reason,data`；state 为 AVAILABLE、NO_DATA、NOT_CONFIGURED、DELAYED、STALE、UNAVAILABLE、NOT_ALLOWED。删除重复且易矛盾的 available 布尔值；原有示例仅供迁移参考。

情绪结果另有 AVAILABLE、LOW_CONFIDENCE、NO_DATA、NOT_ALLOWED。无值时 score/confidence/label 为 NULL，不强行输出中性；有效中性可以为 0。新鲜度阈值按来源许可频率和实测延迟配置，未冻结前不自行宣称 FRESH。

页面包括登录/安全设置、工作台、自选/热门、证券详情、告警规则/事件、来源、词典、死信/重放。每页覆盖 loading、empty、partial error、stale、permission denied；卡片独立超时，切换证券取消旧请求。来源文本转义渲染，不直接 v-html；不从浏览器另抓原文。图表标明版本、粒度、样本和空值，不用颜色作为唯一含义。

## 6. 身份初始化与会话

HTTP + 无限期会话沿用已确认的风险例外，不增加新的局域网访问限制；页面和部署说明持续提示明文传输风险。HttpOnly、SameSite 和 TOTP 无法消除网络窃听，保留 HTTPS 迁移路径。

### 6.1 可执行流程

1. 本机管理命令创建唯一管理员，交互输入密码，生成 TOTP 绑定材料；输出不得进入服务日志或命令历史。
2. 需要网页完成绑定时，本机命令签发一次性、短时、仅绑定用途的 bootstrap 凭据，数据库只存 hash。该上下文只允许获取绑定材料及确认，不允许访问业务 API。
3. 确认 TOTP 后原子启用、消费 bootstrap、生成一次性恢复码并撤销绑定态；正常登录重新验证密码及一个未消费的 TOTP。
4. 正常登录原子消费 TOTP step 并创建随机不透明会话；失败不留有效半成品会话。
5. 丢失 TOTP 时，密码+一次性恢复码原子消费后建立仅恢复用途上下文，完成重新绑定；撤销旧会话及旧恢复码，重新登录。不是永久关闭第二因素。
6. 密码和恢复码均丢失时，只允许本机管理员重置，撤销全部会话并审计。

### 6.2 约束

会话 token 使用密码学随机数，仅 Cookie 保存原值，数据库保存 hash；Cookie HttpOnly、SameSite=Strict、Path=/、不设置 Domain，HTTP 下 Secure=false，HTTPS 迁移后设 true。服务端不设绝对/空闲失效；浏览器会限制 Cookie 保存期，持久 Cookie 的有效期与续写策略在 B 阶段验证，不承诺浏览器永久保存。

CSRF 覆盖普通登录、bootstrap、恢复、注销和业务写入。登录前可建立短时匿名 CSRF 上下文；不能依赖已登录 session 才能获取登录所需 token。Origin 仅允许配置的同源地址，缺失时拒绝浏览器写请求。登录/恢复/再认证限速落持久状态或重启后保守恢复，Redis 故障不放行。

改密、TOTP 变更、恢复码轮换、来源许可/凭证变更需短时再认证。永久会话与短时再认证、bootstrap 的到期语义分开。服务端每请求检查会话撤销及管理员状态，不缓存可能延迟撤销的有效认证结论。

| 处理 | m4_processing_job：输入类型/键、stage、版本、租约、fencing token、重试、输出引用；死信只存安全摘要和输入引用 |
| 情绪 | m5_sentiment_dict/version；单文修订的 m5_sentiment_result；唯一统一 m5_sentiment_window；持久 dirty window、输入变更日志与分析版本发布状态/指针 |
| 告警 | m8_alert_rule/event/delivery；新增 rule+security 冷却状态、告警评估状态/静默记录及不可变事件修正记录；必要的规则评估快照 |
| 运维 | sys_import_batch、sys_idempotency_record、sys_audit_log、sys_maintenance_run；许可撤回/删除登记，备份 manifest 可为受控文件 |

不以本表推断最终表数量。每个实体落实字段、NULL、唯一键和索引后，才生成版本化 DDL。

### 7.2 必须落实的约束

- raw 引用同时携带 `raw_record_id,fetched_date`，包括 job、修订和回查 DAO；不假定分区 id 单列唯一。
- raw 原 `(source,outer_id,fetched_date)` 会吞掉同日正文修订。迁移后去重键含 payload hash 或稳定来源修订号及分区列，网络重复不增事实，真实修订可保存。
- 文档业务键 `(source_code,outer_id)`；修订包含正文 hash、原始引用、发布时间、发现时间、normalizer/parser version 和单文档递增 `revision_order`。来源提供可比较且稳定的修订序号时优先作为新旧判断；否则在接收事务中分配本地观测序号，只表示本系统观测顺序，不代表来源侧绝对新旧。处理版本或正文变化产生新修订，不原地覆盖历史情绪的输入。
- 文档分别记录 `latest_observed_revision` 与 `latest_processed_revision`（及其顺序）。处理结果按修订不可变保存；只有候选修订顺序高于当前 `latest_processed_revision_order` 时，条件更新才可推进当前指针。迟到完成的低序号任务不得回退指针。指针推进、旧/新修订证券关联对应窗口的 dirty 标记在同一事务提交。
- 任务幂等键由 input_type/input_key/stage/processor_version/input_revision 确定；raw 阶段不要求尚不存在的 doc_id。租约记录 owner、lease_until、单调递增 fencing token；提交输出与完成任务检查相同 token，过期 worker 不能覆盖新结果。
- 词典唯一 `(word,dict_type,dict_version)`；snapshot 发布后不可变。分析版本状态为 `DRAFT → BACKFILLING → CATCHING_UP → VALIDATING → ACTIVE`，失败进入 `FAILED`，主动停止进入 `CANCELLED`；active 分析版本指针仅在新版本追平、验证通过后原子切换，查询不混合新旧版本。
- 持久输入变更日志记录会影响分析的新增、修订、证券关联变化和删除/撤权。水位必须是已提交连续水位，不能直接把自增 ID 最大值当作完整水位；分配序号、写变更日志与输入变更在同一事务，且提交顺序可证明（例如锁定并递增对应来源的日志头，直至事务提交）。回算快照、日志水位和版本状态均可恢复、可审计。
- 新增采集覆盖事实，至少包含 `source_code`、订阅范围及版本、业务时间区间、`cursor_before/after`、`run_id`、覆盖状态、原因、Adapter 契约版本、证据引用和 `observed_at`。具体字段/索引按来源能力和订阅模型在 C 阶段冻结。
- V1 情绪按文档修订计算一份，唯一 `(doc_revision_id,engine_level,algo_version,dict_version)`；证券关联决定哪些聚合可纳入该文，不宣称逐证券立场。相反立场多证券文章须标注局限，后续若做目标级情绪须另迁移结果键并评估。
- score 统一 DECIMAL(6,2)、[-100,100]，confidence DECIMAL(5,4)。旧 [-1,1] 数据迁移新列、乘 100、对账后切读，不直接改列造成截断。
- 聚合唯一 `(security_code,window_type,window_end,analysis_version,aggregation_policy_version)`；不维护另一套 15m/1h/24h 平行事实。旧 index 表只作迁移输入或后续明确用途。
- 事件增加 version/status、规则版本、窗口、基线快照及样本策略版本；原触发证据不可静默覆盖，迟到数据修正追加版本化修正事实并保留原值/时间/原因。静默记录保存管理员、适用范围、原因和起止时间；冷却行唯一 `(rule_id,security_code)`；delivery 唯一 `(event_id,channel)`。
- 各引用实体具有到期/删除策略；禁止把删除父表后的失效引用一概当作异常孤儿自动修复。

### 7.3 迁移执行顺序

A：为本次新建的隔离 schema 建立空库与重复启动验收基线（仅在显式 provision 后执行；不盘点、不连接或升级旧库）；B：身份、自选、热门、规范证券键和导入；C：许可、raw 修订、治理与任务；D：分值/词典版本、结果及窗口；E：规则/事件/冷却/投递；F：维护与删除登记。

每次先扩展 nullable/默认值 → 分批回填 → 检测重复/范围/引用 → 新索引 → 切应用读写 → 观察后另版收缩。确切 migration 版本号按实际最大版本递增。MySQL DDL 不等同事务回滚，失败保留现场并向前修复；不盲目 Flyway repair，不改已执行脚本。

运行账号与迁移账号分离；运行账号无 DDL 权限。索引由访问路径和 EXPLAIN 验证；多证券帖子查询以 mention 反向关联为准，不能仅查 normalized_doc 的单一 security_code。

## 8. 单源采集与持久恢复

### 8.1 权限和响应

SourcePolicy 统一检查 ACCESS、STORE_RAW、STORE_NORMALIZED、ANALYZE、DISPLAY、EXPORT，记录许可版本、字段 allowlist 和期限。过期/撤销 fail closed；运行中写库和展示/导出前重查，不能只在调度时检查。

V1 raw-first 流程要求许可允许 raw 保存；不允许时该来源不能接入当前流水线，不能暗中落库。来源 host/scheme/port/path 受审核白名单约束，DNS 解析与每次重定向均校验地址，拒绝未批准主机及内网回跳。

响应同时校验 HTTP、Content-Type、体积、业务码、必需结构及登录/验证码/拦截页特征。401/403/明确拒绝停源；429 遵循 Retry-After/最小间隔；5xx/超时有界退避。阈值来自来源实测及批准配置，测试 fixture 不伪装为真实探针证据。

### 8.2 采集提交协议

1. DB 短事务抢占源租约、生成 fencing token，创建唯一 run；源级并发 1。
2. 事务外请求、校验并提取分页记录，保留 cursor_before。
3. DB 同一提交单元保存该页 raw、持久 PARSE job/待分派标记，并以 expected cursor version+fencing token 更新游标和页状态。
4. 任一写失败该页事务回滚，不推进游标；大批次按来源分页拆小，禁止跨未保存记录跳 cursor。
5. 提交后仅通知内存队列；通知丢失由持久任务扫描恢复。治理失败不回退已安全提交的采集游标。
6. 租约过期可重领；旧 owner 无权提交。重试 raw 与任务幂等冲突返回已保存引用。

永久坏记录只有经批准的隔离策略才能前进：先保存许可允许的输入和拒绝原因并建立可回查记录，否则页面失败停止；不通过忽略异常推进游标。

### 8.2.1 采集覆盖事实与完整性判定

采集 run 成功只表示该 run 完成了其任务，不自动证明业务窗口完整。每个 Adapter 必须声明并版本化可证明覆盖的条件、时间字段语义、分页终止证据、游标可追溯范围，以及来源迟发/回填的已知限制；无法证明时不能返回 `COMPLETE`。

- 每次抓取按订阅范围和业务时间区间持久化覆盖记录，状态为 `COMPLETE`、`PARTIAL`、`UNKNOWN` 或 `UNRECOVERABLE`，记录 run、前后游标、Adapter 契约版本、观察时间及可审计证据引用。`UNKNOWN` 表示现有证据尚不能判定完整与否，仍可能通过探测、重试或对账解决；`UNRECOVERABLE` 表示已知缺口超出来源当前可追溯/回补能力或许可期限，不能通过本系统重试补齐。分页逐页记录提交结果；raw、任务、游标和该页覆盖状态同事务提交。失败页保留 `PARTIAL` 证据，不能将整个区间升级为完整。
- Adapter 只有在所需分页已全部成功、终止条件有证据、游标连续且区间处于来源可追溯范围时，才可声明该区间 `COMPLETE`。仅提供最近 N 条、可能漏掉关机期间内容、发布时间可被回填但无修订/回查能力的来源，不得声称其不可追溯区间完整。
- 某告警窗口只有在该窗口要求的每个来源/订阅范围均被 `COMPLETE` 覆盖、无覆盖空洞，且订阅在对应范围有效时才完整。覆盖证据完整但没有合格内容才是真零；其余状态均按缺失处理，不补零。新加入订阅的生效时间之前没有证据，应显示基线不足。
- 管理员运营视图必须按来源、订阅范围和业务时间区间展示覆盖缺口、状态、原因、最后证据/观察时间及可执行动作。`UNKNOWN` 可触发有界重试、来源探测或游标/分页对账；`UNRECOVERABLE` 可由管理员记录确认人、时间和原因以关闭运维待办，但确认不改变覆盖状态、不补造完整证据。只有新增合法证据覆盖缺口后，才能追加更正记录并重算完整性。
- 当前告警窗口含 `PARTIAL`、`UNKNOWN` 或 `UNRECOVERABLE` 缺口时，该窗口暂停评估并显示 `INCOMPLETE_WINDOW`/“无法评估（覆盖不完整）”，不能显示为无告警。历史基线窗口有缺口则作为缺失样本，不补零；达到最小样本条件前显示 `INSUFFICIENT_BASELINE`。界面需区分可恢复与不可恢复缺口及其原因。
- 若来源无法证明迟发/回填覆盖，或仅提供有限条目且无法追溯缺失区间，产品只显示“已采集声量”，不将其用于完整窗口告警或全量热门排名；来源能力矩阵记录结论及证据，具体能力按来源分别验证。

### 8.3 治理提交协议

Parse → Normalize → Dedup → Entity → Quality → Sentiment。每阶段短事务 claim，事务外计算，短事务写输出、完成当前任务并生成下一任务。崩溃后按租约回收；达到重试上限进入死信；重放新建运行记录引用原输入。

近似重复保存 canonical/duplicate 关系，不删传播证据；canonical 到期时可重选现存代表或标记证据过期，不能读取已删原文。低质量与低置信关联是否纳入统计由版本化策略控制。

## 9. 情绪、聚合和热门

### 9.1 算法交付

规则引擎覆盖分句、最长词匹配、否定、程度、转折、标题/正文权重，保存许可允许的命中词/位置、版本和参数。相同修订与版本输出确定一致。

词典发布前冻结标注集、评价口径和阈值；报告各类 precision/recall/F1、混淆矩阵、覆盖率及低置信样本。confidence 未经概率校准时标注为规则置信指标，不宣称正确概率。无词命中与“有效中性”的边界由标注规范明确，不将未知直接置零。

### 9.2 时间窗口

统一采用滚动窗口，每 15 分钟对齐 Asia/Shanghai 时间点 E，范围 `[E-duration,E)`，duration 为 15m/1h/24h。按业务发布时间归窗，同时保存发现时间。小时和 24 小时不是仅在整点或午夜更新的固定桶；日历仅用于交易日对比，不把全天资讯强行裁掉非交易时段。

迟到、内容修订、实体/去重变化将受影响窗口持久标脏；输入修订变化和 dirty 写入同事务。dirty job 有 generation 和租约，完成时比较 generation，避免计算过程中新增脏标记被清掉。补算仅限仍可合法取得输入的范围；超过期限返回 EVIDENCE_EXPIRED，不声称可完整复算。

聚合只读一个完整分析版本，以 canonical 内容组作为独立情绪样本，不按重复传播条数重复加权。质量、互动、来源权重及衰减公式在 D 阶段冻结并记录 aggregation_policy_version；未校准时使用显式实验状态，不编造权重效果。

#### 分析版本回算、追平与发布

1. 创建不可变版本快照，固定算法、词典、聚合策略及合法可回算范围；进入 `BACKFILLING` 时记录提交安全的输入变更水位 `H0`。原 active 版本在新版本发布前继续服务。
2. 回算 `H0` 对应范围。回算期间所有会影响结果的输入新增、修订、证券关联变化和删除/撤权，必须与业务变更在同一事务写入持久变更日志；日志序号须按已提交顺序可连续追踪，不能只取最大自增 ID。
3. 回算完成进入 `CATCHING_UP`，按日志顺序幂等应用 `H0` 之后的变更，并重算受影响结果/dirty 窗口。输入变更日志消费位置和输出在同事务推进；失败可从最后已提交位置恢复。
4. 待积压接近清零后进入有界发布屏障：暂停会影响发布范围的输入提交，捕获最终水位 `H1`，追平至 `H1`，确认目标范围内无未完成 job/dirty、无缺失输入变更，再进入 `VALIDATING`。屏障最长持续时间与期间允许排队的输入上限由 D 阶段压测、设备与来源能力测量后冻结，并登记参数、依据和证据；未冻结时不得启用在线发布。
5. 屏障超时、输入积压达到上限或验证失败时，必须保持原 active 指针不变、将该发布 attempt 标记为 `FAILED` 并记录失败阶段/原因、释放屏障及相关资源。已提交输入不得丢弃；等待中的新输入按已冻结的有界策略继续处理，达到上限后对新输入实施可见背压/拒绝接收，不得无限排队。失败 attempt 保留为终态审计记录；修复原因后的重试须显式创建新 attempt，从持久水位恢复追平或重启验证，并在新 attempt 中重新通过发布屏障及验证；不得自动延长屏障或在不完整状态下切换。
6. 通过验证后在事务内 CAS 切换 active 指针并设为 `ACTIVE`，随后释放屏障。验证至少对账样本数、修订/删除影响、窗口键与版本键。查询必须在同一请求/快照中固定单一 `analysisVersion`；明确记录版本的可比起止范围及证据状态，归档结果不自动与当前版本拼接为连续同口径序列。
7. 回滚窗口内若旧版本未持续消费输入变更日志，回滚前须在发布屏障下先将旧版本追平并验证，再原子切回；不得仅因旧版本仍在库中就假设其可直接恢复服务。版本日志保留期限不得超过相关内容许可期限。

热门候选采用最近 24h、同样 15 分钟对齐的有效声量排名，按声量降序、规范证券键升序稳定排序；手动热门不自动被替换。来源不具备许可的互动/行情字段不参与排名。

## 10. 站内声量告警

### 10.1 统计口径

既定阈值保持：15 分钟至少 10 条，且达到过去 7 天同一时段均值 2 倍，冷却 30 分钟。

本版统一为：每 15 分钟对齐 E，当前 `[E-15m,E)`；历史为前 1…7 个自然日的相同时段，不加“同星期”筛选，不改成 7 个交易日。源时段已完整观测且无合格内容记 0；未运行、停机、来源异常、缺页或未补完记缺失，不能补 0。

声量按不同 `(source_code,outer_id)` 的合格证券关联内容计数，同文反复抓取/修订只算一次；不同来源项的近似转载保留传播计数。情绪按 canonical 独立样本聚合，两类计数需在界面及证据中明确区分。

历史最少有效时段数 `baseline_min_samples` 在 E 阶段生产启用前由 PO 冻结，范围 1…7；本版不代替用户决定。基线为有效时段计数的算术均值，保存各日值和有效性。全部有效历史均为 0 时仍按既定不等式判断，不计算除以零的倍数；证据 ratio=NULL、reason=ZERO_BASELINE。

判断为：当前时段完整、历史样本足够、C>=10 且 C>=2B、未冷却/静默/每日限额抑制。缺采显示 INCOMPLETE_WINDOW，历史不足显示 INSUFFICIENT_BASELINE。采集健康与空结果分开，不能用“最新一条新闻时间”推断是否完整。

告警评估状态与已生成事件状态分离：覆盖不完整时将受影响的规则/证券/窗口标记为 `EVALUATION_SUSPENDED`，显示原因和覆盖状态；该状态不是“未触发”或“无告警”。人工静默只抑制静默范围及有效期内的新事件，不改变采集、覆盖或统计状态；必须记录操作者、范围、原因、开始/结束时间，审计并在界面标明静默中及恢复时间。

### 10.2 并发和生命周期

对 rule/security 冷却状态行加锁；在同一事务重新确认规则版本、插入确定性 dedup 事件、更新 cooldown_until/当日计数、插入 IN_APP delivery/outbox。跨证券每日上限若按规则全局计算，还须锁规则日计数行，固定加锁顺序防死锁。

event key 包含 rule_id、rule_version、security、window_end、metric。事件状态统一 `TRIGGERED → ACKNOWLEDGED | DISMISSED`，两种处理态为终态；V1 不保留无对应业务动作的 RESOLVED。重复相同操作幂等，不同终态转换返回 409。

事件与站内可见事实同库提交。轮询可恢复未读结果；WS 失败不影响事件。未读=TRIGGERED，ack/dismiss 后移出未读。

默认规则参数为 15m/10/2/7d/1800s。管理员按已确认基线可调整开放字段，但服务端限制值域并保留 rule_version；最小历史样本、静默和每日限额在启用时显式配置，不将文档示例 maxPerDay=5 视为已确认需求。

关机补采和管理员重放默认只修复统计，不补发旧告警。实时评估允许的完成延迟/等待预算须在来源实测后冻结；超出预算时标记 MISSED_WINDOW，不能在恢复后集中推送历史事件。

来源恢复后先补齐可追溯范围并重算统计/覆盖，再恢复后续窗口评估；默认不为已过截止点的窗口补发告警。已触发事件的原始窗口、计数、基线及证据引用不可静默改写或自动撤回；若迟到/修订数据改变统计依据，追加可审计的事件修正记录和修正后证据，保留原值/时间/原因，并按待冻结的通知策略提示用户。事件状态仍按既定 `TRIGGERED → ACKNOWLEDGED | DISMISSED` 转换，不因修正而隐式改变。

## 11. 导入、导出和内容生命周期

预览保存归属、文件 hash、规范化行、校验版本、有效期和错误行；commit 绑定 batch+幂等键，重新校验证券/容量/权限。自选小批量原子提交，失败不部分加入；主数据大批量可分批但须提供行级状态与恢复位置。XLSX 只读数据，不执行宏/公式/外部链接；限制压缩展开量与文件行数。导出将非业务公式字段作为文本写入，防止公式注入。

| 类别 | 上限 | 清理对象 |
|---|---:|---|
| Raw | 7 天 | payload、受限原始附件及对应缓存 |
| 规范化/情绪内容 | 90 天 | 正文/摘要、修订、命中证据、逐文情绪、实体/重复关系 |
| 聚合/告警/分析 | 1 年 | 不含禁止长期保存的原文或派生字段；许可优先 |
| 行情 | 日线 1 年、分时 30 天 | 后续阶段才启用 |

期限取产品上限与来源条款较短者；保留起算点在来源接入矩阵中明确，不能通过重抓/修订无限延长。raw 7 天后追溯显示原始证据已过期，剩余修订仍可在许可期间解释；90 天后历史聚合只保留允许的统计，不能承诺逐帖复算。

实体到期或撤权时先在事务中将生命周期标记为 `EXPIRING/REVOKED` 并递增 `lifecycle_version`，再异步分批清理。worker 计算可在事务外进行，但提交派生结果前必须锁定/条件检查输入状态、许可状态和捕获的 lifecycle_version；状态已变或版本不一致时拒绝提交，并将任务转为不重试的过期/撤权结果。输入状态转换、派生提交检查及撤权/删除登记必须通过同一实体锁或等价 CAS 形成提交屏障，禁止旧 worker 在清理后重建派生内容。清理可恢复，最终再次扫描确认无残留；删除登记仅保存必要非内容信息。

清理覆盖 job/dead letter、标注集、导入/导出临时文件、缓存和告警 evidence。调度清理需先完成 dry-run 和批量/分区边界测试；已批准周期策略无需每日人工确认。备份门禁未过不允许生产写入，不能因此停掉已到期数据的清理。

按日/月分区不能保证精确 7 天期限：采用行级到期清理，只有整分区记录均到期才 DROP。不同来源期限混存时不能按统一日期整分区删除。监控未来分区、p_max 和清理积压。

## 12. 原生部署、备份与恢复

### 12.1 平台

Windows 用 PowerShell 检查 JDK/MySQL、端口、ACL、磁盘、服务账号及休眠/重启；Node/Maven 只需构建机，生产不运行 Vite dev server。前端 dist 与 JAR 同源提供，版本目录与配置/数据分离。

DSM 先实测型号、架构、Java 17、真正的 MySQL 8 可用性、持久目录、服务/自启动和权限；不能默认套件 MariaDB 等同 MySQL 8。设备不满足时回退 Windows，不偷偷改用容器。DSM 侧脚本采用实机支持的 shell/服务机制；PowerShell 可在 Windows 侧执行远程预检，不假定 DSM 安装 PowerShell。

### 12.2 备份

加密和密钥保管决定前 backup.enabled=false，禁止正式发布。决定记录允许选择经明确接受的非加密方案；不能一边称加密未决，一边把强制某算法写成已确认。若选择加密，密钥离开数据库和备份副本独立保管，并验证解密。

每日一致性备份 NAS、保留 7 份，每月隔离恢复；RPO 24 小时、RTO 1 个工作日为待实测目标。备份覆盖 DB、必要配置/算法词典版本、文件附件及独立保管密钥的恢复引用。NAS 同设备副本不能抵御整机故障。

备份不能绕过来源最长留存：来源条款必须明确备份副本处理方式；未允许额外备份留存时，通过排除受限内容、合规到期清理或禁止该备份方案解决，不能默认每份备份额外保留 7 天正文。

### 12.3 恢复和升级

先隔离恢复并校验 checksum、schema/索引、计数、关键查询及密钥可用性。恢复默认关闭外部调度，撤销会话，重建源租约/任务状态；以独立于旧备份保存的许可撤回与删除登记重新清理，阻止恢复复活已撤权内容。校验完成后才切生产。

升级先确认恢复点、暂停写任务、迁移、发布同版前后端、readiness 和冒烟。应用回退仅在新 schema 对旧应用兼容时允许；不兼容先维护停机及向前修复，不能默认回退 JAR 就可恢复业务。

### 13.1 A 阶段登记表闭环演练

A 阶段退出前，PO 与对应负责人须使用[运行与验收登记表 §4](./运行与验收登记表.md#4-a-阶段闭环演练)选择至少一条仍适用的真实待确认项，完整记录“待确认事实 → 负责人决策 → 证据 → 门禁结论”。本次批准范围内的 G01 已记为 `N/A`，不执行 G01 演练；可闭环其他适用项，G02–G05 仍按各自门禁要求处理。

演练必须区分事实、决策和证据：事实写可复核的当前状态及来源；决策由登记的负责人明确作出并注明人/日期；证据链接到盘点、测试或批准记录；门禁结论按既有规则记为通过、阻断或仍未决，并说明允许/禁止的后续工作。任何一环缺失时不得标记 `PASSED`，门禁保持 `OPEN` 或 `BLOCKED`。演练用于验证登记流程，不授权恢复源码、执行生产迁移、启用真实采集或绕过既有门禁。登记表中的演练记录须引用 A 阶段实际产物；不得把本文件示例、计划值或口头假设当作已取得证据。

### 14.1 必测路径

| 范围 | 关键验证 |

| 迁移 | 显式 provision 的隔离新库空库、重复启动、当前新项目支持版本升级、NULL/唯一键冲突、失败阻止 worker；真实 MySQL 验证。不得连接或迁移旧库 |

### 14.2 发布判定

先判断阻断缺陷，再判断所选交付模式的门禁：

- BLOCKED：存在 P0/P1、实际未授权采集/展示、迁移破坏、数据丢失、恢复失败等问题；禁止发布。
- RESTRICTED：核心离线闭环可用但生产来源、所选平台或备份门禁不齐；仅受控验收，相应能力关闭。
- READY：所选部署平台实测通过，真实生产来源及全部适用门禁通过，恢复和核心旅程成功，P0/P1 为零；按已验证容量发布。

Windows 已通过且选择 Windows 发布时，未验证的 DSM 是不适用项，不阻止 Windows READY，但不能宣称 DSM 支持。没有来源授权与实际违反授权是不同状态，前者可离线受限验收，后者 BLOCKED。已接受 HTTP 风险不豁免 CSRF、权限、凭证存储和恢复控制。
