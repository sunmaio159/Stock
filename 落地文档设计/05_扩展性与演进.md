# 05 扩展性与演进

> 版本：V2.1（2026-10-03）

## 一、扩展性设计原则

V1 单机单实例是**显式决策**（≤100 用户 / 50 并发），但不是"焊死"：通过六个接口接缝 + 数据层预留，保证 V2-V4 演进**只换实现、不改调用方、不搬数据**。

## 二、六个演进接缝（V1 只抽象接口，不引入组件）

| # | 接缝 | 接口 | V1 实现 | V2+ 替换 | 触发条件 |
|:-:|---|---|---|---|---|
| 1 | 任务异步化 | `TaskDispatcher` | 进程内队列 | Redis Stream / RocketMQ | 治理吞吐 >50 帖/s 持续 |
| 2 | 推送 | `PushChannel` | WS 直推 | 统一消息网关 | 多实例部署 |
| 3 | 配置中心 | `ConfigProvider` | DB + Redis pub | Nacos / Apollo | 配置项 >50 或多实例 |
| 4 | 规则引擎 | `RuleEvaluator` | 白名单 switch | DSL 条件树引擎 | V2 告警 DSL 落地时 |
| 5 | 回放编排 | `ReplayOrchestrator` | 同步 HTTP 触发 | 异步任务编排 | 重放窗口 >7 天需求 |
| 6 | 事件总线 | `DomainEventPublisher` | Spring Event | MQ | 跨模块事件 >5 类 |

**纪律**：接缝接口可以定义，实现必须仍是单机版；V1 禁止引入任何分布式组件（Kafka/ES/CK/Milvus/Nacos 全部在 Won't 清单）。

## 三、容量外推（何时必须升级）

| 指标 | V1 设计值 | 扩容阈值 | 升级路径 |
|---|---|---|---|
| 日帖量 | 5 万 | >20 万 | 治理队列→MQ；m4/m5 按月分表 |
| 注册用户 | ≤100 | >1000 | WS 独立部署 + Redis Pub/Sub 广播（协议已预留） |
| 详情页 QPS | 50 并发 | P95 持续 >800ms | 卡片缓存预热 + ES 接管帖文检索 |
| MySQL 存储 | ~16GB/半年 | >60GB | raw 迁对象存储；历史数据迁 ClickHouse（V4） |
| 标的覆盖 | 活跃 2000 吧 | 全市场 5400 | 采集任务分片（sourceLock 已按源隔离，天然可分片） |
| 情感精度 | L1 ≥75% | 标注集 ≥3000 条 | L2 FinBERT 上线（BudgetRouter 路由框架已就位） |

**表结构演进规则**（与 03 API"响应只增不删"纪律对等）：V2+ 对 V1 既有表的扩展**仅允许增列，禁删列、禁改既有列语义**（Flyway 增量迁移）。已预告的典型扩列：`m5_sentiment_index_15m` 在 V2 突增三模型上线时增列 `sample_post_count`/`signal_level`/`confidence`（对齐日频表口径）。

## 四、版本演进路线（定稿）

| 版本 | 周期 | 交付 | 依赖本版预留 |
|---|---|---|---|
| **V1** | 6 周 | 14 项交付（见 06） | — |
| **V2 增强** | +6 周 | 突增三模型（Z-Score/情绪反转）、技术/资金/基本面卡、四维选股、告警 DSL 引擎+可视化编辑器、移动适配、行情日K/公告/资金采集 | 15min 基线表、RuleEvaluator 接缝、m6_quote_daily 已启用 |
| **V3 智能** | +8 周 | 综合评分卡+因子表化（ana_factor_def 权重唯一来源）、L2 FinBERT、AI 助手（日报/RAG）、OpenAPI+Webhook、题材图谱 | BudgetRouter 路由、dict/algo 版本化、作者画像表 |
| **V4 规模化** | 持续 | 多实例+负载均衡、数据分层（ES/CK）、多租户 | 六接缝、Redis 广播频道设计 |

## 五、已知技术债与偿还计划

| 债 | 现状 | 偿还点 |
|---|---|---|
| 单机 SPOF | 日备+binlog，RTO 1h | V4 主从+多实例 |
| MySQL LIKE 搜索 | 前缀索引够用 | V2 数据量上来后 ES |
| L1 规则精度 | 75% 门槛 + 参考信号定位 | V3 L2 模型 |
| 治理完整版（审计页/词典回滚 API/倒排索引） | V1 最小集 | V2 |
| 同步调用耦合理查 | 队列+接缝缓解 | V2 MQ |

## 六、扩展性反模式（明令禁止）

1. 为"将来可能"提前引入 MQ/ES/CK——用接缝代替组件
2. 在 V1 代码里写多实例分布式锁——WS 广播协议已预留，到时启用即可
3. 行情数据塞进治理流水线——分层铁律，违反即架构返工
4. 评分卡权重硬编码——V3 落地时只能读 `ana_factor_def`
