# 细化一：V1 MVP 落地实施计划（6 周）

> **文档性质**：对 `阶段1-2_需求与架构设计.md` §1.3.3 MVP 边界 与 `阶段4-5_界面与落地评估.md` §5.4 路线图 的可执行化拆解
> **目标读者**：实际执行开发的后端/前端/算法工程师
> **原则**：每周有可演示产物；关键路径（采集→治理→情感）优先打通再优化；每任务含验收标准

---

## 1. 总览：里程碑与关键路径

```
W0 工程奠基 ──→ W1 主数据+账户 ──→ W2 采集链路 ──→ W3 治理+情感 ──→ W4 情绪指数+详情页 ──→ W5 告警+WS ──→ W6 联调压测上线
                  │                  │                │                  │                    │
                  └────────── 关键路径：M2证券主数据 → M3采集 → M4治理 → M5情感(L1) → 情绪指数 → 详情页/告警 ──────────┘
```

**关键路径**（延迟即整体延迟）：M2 证券主数据导入 → M3 东财股吧 Adapter → M4 治理四 Worker → M5 L1 引擎 → 情绪指数日频计算 → 个股详情页舆情卡片。

**并行支线**（不阻塞主链路）：M1 登录/自选股、前端工作台框架、M8 基础告警、运营后台骨架。

**每周末 Demo 日**：周五下午演示当周产物，未通过验收的任务自动滚入下周并标记风险。

## 4. W2：采集链路（M3，主数据源 = 东财股吧）

| # | 任务 | 说明 | 验收标准 |
|:-:|---|---|---|
| 2.1 | SourceConfig + 策略引擎 | `m3_source_config` 加载缓存；令牌桶限流（guava RateLimiter 或自实现）；三态熔断器（连续失败 5 次开路，30s 半开） | 单测覆盖三态迁移；限流 QPS 可配置生效 |
| 2.2 | Adapter SPI | `SourceAdapter` 接口：`fetchList/fetchDetail/parse/schema`；Spring 插件化注册 | 新增源只需实现接口 + DB 插入一行配置 |
| 2.3 | 东财股吧 Adapter | 列表 API 直连（JSON），帖 ID 游标增量；Schema 校验 + 字段漂移分级（P1 阻断告警 / P2 P3 放行记日志） | 单源跑通：抓取→RawRecord 落库→parse→NormalizedDoc 候选 |
| 2.4 | RawRecord 落库 | `INSERT...ON DUPLICATE KEY UPDATE`（uk_source_outer）；原始报文写入分区表 | 重复执行同一任务不产生重复行；content_hash 一致 |
| 2.5 | 调度器 | ThreadPoolTaskScheduler(8) + 每源 AtomicBoolean 防重入；cron 表化 | 东财源按 5min 周期稳定触发；手动触发接口可用 |
| 2.6 | 雪球/同花顺 Adapter | HTML/JSON 适配，10/15min 增量 | 三源并行 24h：成功率 ≥ 99%，日帖量 ≥ 5 万 |
| 2.7 | 采集记账 | 每任务记录 success/fail/duration/cost → `m3_task_instance` + 指标暴露 | 运营后台可查到每源当日成功率 |

**风险预案（TR1 反爬）**：东财接口限流收紧时——降频至 10min、切换备用 endpoint、UA/Cookie 参数化热更新。W2 必须实测 72 小时连续运行。

**W2 出口条件**：三源连续运行 72h，成功率 ≥ 99%，RawRecord 与解析数据量一致（对账误差 < 0.1%）。

## 5. W3：治理流水线 + L1 情感引擎（M4 + M5 核心）

| # | 任务 | 说明 | 验收标准 |
|:-:|---|---|---|
| 3.1 | 治理编排 | LinkedBlockingQueue 串联 Clean→Dedup→Entity→Quality；消费失败重试 3 次后入死信表 | 从 RawRecord 到 NormalizedDoc 端到端 P95 ≤ 30s |
| 3.2 | CleanWorker | 去 HTML/广告正则/繁简转换(opencc4j)/5000 字截断 | 广告样本集（100 条）清除率 ≥ 95% |
| 3.3 | DedupWorker | SimHash64 + 汉明距离 ≤ 3；近 24h 候选集比对（Redis Set 缓存 simhash） | 重复帖召回率 ≥ 90%，误判率 ≤ 5%（抽样人工核验） |
| 3.4 | EntityWorker | AC 自动机（aho-corasick 库），词典 = m2_security 名称+简称别名表；提取主标的写 `security_code` | 实体抽取准确率 ≥ 95%（抽样 200 条） |
| 3.5 | QualityWorker | 水军规则（注册时长/发帖频率/重复内容占比）+ 字数/互动启发式 → quality_score 1-5 | 水军样本集过滤率 ≥ 85% |
| 3.6 | L1 规则引擎 | 金融情感词典（正/负词表入库可后台维护）+ 否定词翻转 + 程度副词加权 + 转折句规则 → label + score[-1,1] + confidence | 人工标注 500 条验证集：三分类准确率 ≥ 75%（L1 达标线） |
| 3.7 | BudgetRouter 骨架 | V1 全部路由 L1；保留 engine_level 字段与路由接口 | m5_sentiment_result 正确写入，engine_level=1 |

**W3 出口条件**：任选一只活跃股吧标的，当日治理后帖文可查（API11），每帖带情感标签，人工抽检 50 条情感标注合理率 ≥ 75%。

## 6. W4：情绪指数 + 个股详情页（M5 派生 + M6 详情页）

| # | 任务 | 说明 | 验收标准 |
|:-:|---|---|---|
| 4.1 | 情绪指数日频计算 | 收盘后批任务（18:00 前完成）：按 wk 加权公式聚合当日 SentimentResult → `m5_sentiment_index`；板块指数 = 成分股加权 | API12 返回 30 日趋势；公式权重明细存 `weight_detail` |
| 4.2 | 15min 派生表 | 盘中每 15min 滚动更新当日指数（为 V2 突增检测铺垫数据） | 盘中指数延迟 ≤ 15min |
| 4.3 | 行情快照（简版） | 自选股 3-5s 快照轮询（免费行情 API 或东财 push2 接口），写 Redis | 工作台自选股价格 3-5s 刷新 |
| 4.4 | 详情页聚合 API | API15：七卡片组装；舆情/速览 V1 真实数据，技术/资金/基本面 V1 占位（返回 `available:false`） | 首屏（速览+舆情）P95 ≤ 800ms；Redis 缓存 5min |
| 4.5 | 详情页前端 | 七卡片布局、舆情卡片（指数趋势图 + 帖文流 + 情感分布饼图） | 按分册 C §4.3 视觉稿还原 |
| 4.6 | 工作台前端 | 五大卡片：自选行情、情绪红黑榜、热帖 Top10、公告占位、告警占位 | 按分册 C §4.2 还原；一屏加载 ≤ 1.5s |

**W4 出口条件**：详情页速览卡+舆情卡真实可用；工作台一屏式呈现；800ms 首屏 SLA 实测达标（100 次采样）。

## 7. W5：WebSocket + 基础告警（M8 基础）

| # | 任务 | 说明 | 验收标准 |
|:-:|---|---|---|
| 5.1 | WS 通道 | Spring WebSocket + STOMP；认证、心跳 10s、`/user/queue/quote` 行情推送 | 断线指数退避重连正常；单用户 3 连接上限生效 |
| 5.2 | 价格告警 | 简单规则（价格 ≥/≤ 阈值），DB 表 + 轮询行情快照触发 | 触发到推送 ≤ 10s |
| 5.3 | 声量突增告警（简版） | 当日累计帖量 > 昨日同期 ×3 且绝对值 > 30（先用环比单模型，Z-Score 留 V2） | 命中即推送站内 + 企微 |
| 5.4 | 企微推送 | 群机器人 webhook 通道 + 站内信 | 告警消息含跳转链接 `/securities/{code}` |
| 5.5 | 降噪基础 | 同标的同类事件 15min 合并；每规则日上限 | 连续触发不刷屏（压测验证） |

**W5 出口条件**：自选股价格/声量告警端到端可收到企微消息，15min 合并生效。
