## 一、P0 缺陷（阻断级：启动即崩溃 / 设计无法落地）

### P0-1 L1 情感引擎初始化即抛异常（分册 B §3.3.1）

`Map.ofEntries` 中 **"大幅" 出现两次**（重复 key）→ `IllegalArgumentException`，Bean 初始化失败，应用无法启动。
同段 `Set.of` 否定词中 **"不" 重复**（`"不", ..., "不"`）→ 同样抛异常。
**修复**：去重；词典入库（细化2 `m5_sentiment_dict`）后此硬编码整体删除，bug 自然消失。词典加载从 DB 读取是正确方向，应作为唯一实现，不要保留硬编码版本。

### P0-2 治理流水线事务边界错误（分册 B §3.2.5）

`processInternal` 上标注 `@Transactional`，包裹**整批循环 + 同步情感分析调用**。后果：
1. 长事务持有 DB 连接，500 条/批时连接耗尽风险；
2. 循环内 `catch` 吞掉异常后 Spring 事务仍被标记 rollback-only → 整批回滚，前 N-1 条白处理；
3. 情感分析（非 DB 操作）被卷入事务，延迟放大。

**修复**：去掉方法级 `@Transactional`；`persistDoc` 单条加事务；情感分析移出事务、异步投递（细化4 的队列拓扑已给出）。

### P0-3 采集限流是无效实现（分册 B §3.1.1）

```java
String current = redisTemplate.opsForValue().get(rateLimitKey);
if (current != null && Integer.parseInt(current) >= maxQps) { return; }
```
只 `get` 不 `incr`，计数器永远为 null → **限流从未生效**。对一个靠爬取生存的系统，这是会被封 IP 的缺陷。
**修复**：改为令牌桶（Guava RateLimiter，每源一个实例，放 `CrawlContext.acquireRatePermit()` 里——伪代码里其实已调用该方法但调度层又写了这段冗余且错误的逻辑，两处去其一）；或 Redis `INCR + EXPIRE 1s` 滑动窗口。

### P0-4 增量游标只存 Redis（分册 B §3.1.1）

`crawl:cursor:{taskId}` 仅存 Redis，无 TTL 无持久化。Redis 重启/淘汰 → 游标丢失 → **全量重采**（东财股吧 2000 吧 × 全量分页，必然触发反爬）。且游标在任务成功前即 `set`，失败时游标已前进 → 数据漏采。
**修复**：游标以 DB（`m3_source_config.last_cursor`，细化2 已有此字段）为准，Redis 只作读缓存；游标仅在整批落库成功后更新（at-least-once，配合幂等键消费重复）。

## 二、P1 缺陷（跨文档自相矛盾，必须仲裁）

> 这些矛盾不修复，开发时必然各执一词。建议在主文档增加「设计基线仲裁规则」：**冲突时以主文档+细化文档为准，分册 B 伪代码仅为思路参考**。

### P1-1 情绪指数量纲三套并存

| 出处 | 量纲 |
|---|---|
| 主文档 §4.4 公式 `Si = 100×Σ(wk×score)/Σ(wk)`（score∈[-1,1]） | **[-100, 100]** |
| 分册 A DDL `m5_sentiment_index` 注释 + UI 温度计 + TC-011 预期 | **[0, 100]** |
| 分册 B §3.3.3 代码注释 `setSentimentIndex // [-100, 100]` | [-100, 100] |

**仲裁**：统一为 **[0, 100]**（对 UI/告警/选股条件最友好），公式改为 `Si = 50 + 50 × Σ(wk×score)/Σ(wk)`，中性 = 50。同步修改 B 伪代码与所有阈值（如选股条件"情绪指数>60"语义不变）。

### P1-2 评分卡权重两版并存

主文档公式 `0.25×基本面` vs 分册 A 需求表 F-R05 `基本面20%`；B 代码用 0.25。
**仲裁**：以主文档为准（25/20/20/20/15），删除 F-R05 行的 20% 写法。同时把权重改为从 `ana_factor_def` 读取而非代码常量（B §3.4.1 硬编码常量与 §3.4.2"表化"自相矛盾，应只有表化一条路径）。

### P1-3 V1 范围三个版本

| 项 | 分册 A MVP 清单 | 分册 C §5.3.1 | 分册 A 数据源矩阵 |
|---|---|---|---|
| 采集源 | 东财+雪球+同花顺 | 东财+雪球+**RSS** | 同花顺 V1 ✅ |
| WebSocket | V1 Must #13 | 未列入 V1 | — |
| 告警 | V1 Must #14（企微+站内） | 仅"骨架" | — |
| L2 模型 | V3（Could） | — | gantt 放 V2a |
| 评分卡 | V3（F-R05） | — | gantt 放 V2a |

**仲裁**（推荐基线，与细化1对齐）：采集源 = 东财+雪球+同花顺（舆情三源，RSS 属新闻源不是替代）；WS 与基础告警保留在 V1；L2 模型固定 V3；评分卡固定 V3（gantt 中 V2a 的"评分卡"移到 V3，V2 改为只做因子计算）。分册 C §5.3.1/5.4 需要修订。

### P1-4 表命名体系双轨

分册 A DDL：`m3_raw_record` / `m4_normalized_doc` / `m5_sentiment_result`；
分册 B 伪代码：`crawl_raw_record` / `crawl_task_run` / `crawl_source_health` / `doc_post` / `doc_news` —— 这些表在 DDL 中**根本不存在**，且 B 把行情 K 线也塞进 `NormalizedDoc`（一个类同时承载帖子 title/author 和 OHLC，异构混用）。
**仲裁**：以细化2 的 21 张表为唯一事实源。B 中 `crawl_source_health` 的功能并入 `m3_source_config`（熔断字段已有）；`doc_post/doc_news` 统一为 `m4_normalized_doc`（`source_type` 区分）；行情数据**禁止**走 NormalizedDoc，V2 落 `m6_quote_daily`。

### P1-5 熔断器状态机二态 vs 三态

A DDL `circuit_state: 0闭合/1开路/2半开`；B 代码用 `boolean + circuitBreakUntil`（二态+时间）。
**仲裁**：三态。半开不是"到点自动闭合"（B 的 `isSourceHealthy` 里到点就置 false 直接放行，等于没有半开探测），而是**放行 1 个探测请求**：成功→闭合+清零失败数；失败→重新开路并指数退避（30s→2min→10min→30min 封顶）。

### P1-6 日频任务时间三个版本

16:00（B §3.4.3 cron）/ 17:00（细化4）/ 18:00 前完成（C SLA）。
**仲裁**：统一 **17:00 触发、18:00 前完成**（SLA 不变，给重试留 1h）。评分快照同窗口。

### P1-7 "交易日"判断缺失（代码级系统性 bug）

- `AnomalyDetector` 环比用 `minusDays(1)`：周一对比周日（无数据=0）→ **每周一开盘必报假突增**；
- 多处 cron 用 `MON-FRI`，法定节假日照常跑；
- 多处 `LocalDate.now()` 未固定时区。
**修复**：所有日级逻辑必须过 `m2_trade_calendar`（细化2 已建表）；全局 `Clock` 固定 `Asia/Shanghai`；JVM 参数 `-Duser.timezone=Asia/Shanghai`。

### P1-8 规模与可用性指标互斥

并发 200 用户（C §5.1.3）vs 成本按 1-10 用户（C §5.3.3）vs V1 目标注册 100/DAU 30（C §5.6.5）；可用性主文档 99.5% vs C V1 目标 99.0%。
**仲裁**：V1 定位个人/小团队内部使用——压测按 50 并发设计（200 并发降级为 V2 指标），可用性统一 **99.0%（V1）**→ 99.5%（V2）。成本表 ¥18,790/年维持。

## 三、P2 缺陷（伪代码级技术错误，开发前修订）

| # | 位置 | 问题 | 修复 |
|---|---|---|---|
| 1 | B §3.1.1 | 扫描循环 `scheduleAtFixedRate` 与任务 `submit` 共用 8 线程池，长任务饿死调度 | 扫描单线程独立；任务池 `ThreadPoolExecutor(8, CallerRunsPolicy)` 分离 |
| 2 | B §3.2.2 | SimHash 比对全量遍历 Redis Set（O(n)/帖）；溢出直接 `delete` 整个索引 → 24h 窗口去重瞬间失效 | 细化4 分桶方案（高 16 位分桶）；溢出按时间分桶淘汰最旧桶 |
| 3 | B §3.2.4 | `authorPostKey` 用昵称做 key（跨源同名碰撞）；`increment` 后 `expire` 非原子 | key 改为 `source:authorId`；用 Lua 或 `incr`+首次 setnx 带 TTL |
| 4 | B §3.3.1 | `inTransitionClause` 一旦 true 永不复位 → 转折加权跨句传播到文末 | 遇句读符号（。！？；）复位 |
| 5 | B §3.3.1 | 分词只在词典命中时切词，否定窗口"前 2 token"对长词失效（"并不特别看好"） | 引入真分词（ansj/hanlp），或否定窗口按字符距离 ≤4 |
| 6 | B §3.3.2 | L3 降级到 L1 后 `setEngineLevel("L3")` 覆盖实际级别 → 结果表级别失真，L2 训练数据污染 | 记录**实际执行**级别，另加 `requested_level` 字段 |
| 7 | B §3.3.3 | `w_time` 用 `now()`（计算时刻）→ 同一天 17:00 和 23:00 算出的日指数不同，快照不可复现 | 日频任务以"交易日收盘时刻"为衰减基准点 |
| 8 | B §3.4.1 | `zscoreNormalize` 是 clamp 假实现，"z-score 标准化+行业对标"实际不存在 | V3 落地前改真 z-score（行业内 μ/σ，样本<10 用全市场兜底），UI 标注"简化版" |
| 9 | B §3.4.2 | `evaluateExpression` default 分支引用不存在的局部变量 `factor`（编译错误）；表达式 switch 与"表达式引擎"注释不符 | 用 Aviator/SpEL，或诚实改为"枚举路由"并改名 |
| 10 | B §3.4.3 | `selectAllScoredStocks(today)` 取数逻辑倒置（只快照"已评过分的"=永远只快照第一批） | 快照范围 = 全市场或全部自选标的并集 |
| 11 | B §3.2.3 | 实体词典硬编码 5 只股票，无热更新 | 词典 = `m2_security` + `m2_security_alias`（细化2），后台维护后 Redis pub 通知重建 AC 自动机（双 buffer 切换） |
| 12 | A §2.2.4 vs B §3.2.1 | 截断长度 5000 字 vs 2000 字 | 统一 **5000 字**（帖子正文），标题 100 字 |
| 13 | A §2.3 | 缺 `POST /api/auth/refresh`、注册端点；`m2_security` 无拼音列但 API06 承诺拼音搜索 | 细化3 已补 refresh；拼音列加到 `m2_security_alias(alias_type=2)` 复用 |
