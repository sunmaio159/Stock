## 四、修订根因分析

V1.2 的核心问题在于：
1. **文档只定义了"理想态"**，15% 公式有数学错误，且未做可执行性推演
2. **多个系统间缺少"运行时一致性"约束**（如线程池策略与扫描线程解耦的冲突未被发现）
3. **用户价值闭环不完整**：缺失行情数据使"价格突破"告警不可用；无情感词典管理使情绪引擎无法迭代
4. **运维和合规设计缺位**：无备份、无分区维护、无审计、无安全测试

V1.3 的修复策略：
- **第一遍**：三册文档交叉校核（00/01/02/03）→ 优先消除数学不一致
- **第二遍**：CodeBuddy + Copilot Free 评审，52 条缺陷精确到代码行
- **第三遍**：输出 10 册 V1.3 文档，每条缺陷有修复方案、验收标准、责任人和最大排期窗口

## 五、遗留可接受风险

| 风险 | 理由 |
|---|---|
| V1 仅单机部署 | 设计并发 ≤50，单机 4C8G 足够 |
| L1 准确率仅 ≥75% | "参考信号"定位，P95 延迟优先 |
| 详评与综合评分卡锁定 | 锁定设计留 V3，防范围蔓延 |
| 仅企业微信+站内信 | 其他渠道进 V2 |
| V1 无 L2/L3 | 保护复杂度在安全线内 |
